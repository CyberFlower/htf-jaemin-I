# GOAL: 다녀왔습니다 (`GRD`)

> 상태: **Draft** (팀 합의 전). 원본: [draft/proposal-grandma.html](../../draft/proposal-grandma.html) (v0.1)

## 한 줄 정의

가족 채팅방의 "언제 한번 가자"를, 차량이 함께 실제로 다녀온 하루로 만든다.

### 제품 목적

기본 목적은 **사용자의 맥락을 증강하고, 이를 바탕으로 여정에 가치 있는 정보를 전달하는 것**입니다. 사람·장소·기억·약속에 현재의 의도·동행자·환경·차량 상태를 연결하고, 사용자가 이번 여정을 판단하고 준비하는 데 도움이 되는 정보로 돌려줍니다. 확인된 여정 결과는 다음 안내의 맥락이 됩니다.

가족 동행은 이 목적을 보여 주는 대표 시나리오입니다. 가족 외 타깃으로의 확대는 정하지 않았습니다. 이 목적을 Goal에 어떻게 명시하고 검증할지는 [GRD-Q16](OPEN_QUESTIONS.md)에서 다룹니다.

중심 경험([GRD-UC-011](USE_CASES.md))을 검토하는 기준:

- 같은 목적지라도 확인된 동행자·약속·현재 조건이 달라지면 어떤 안내가 달라지는지 설명할 수 있다.
- 안내에는 왜 지금 이 사용자에게 관련 있는지, 어떤 기억·관측·외부 정보에 근거하는지가 드러난다.
- 모르는 정보와 확인된 정보를 구분하며, 잘못된 맥락을 사용자가 수정할 수 있다.
- 확인된 방문·약속 완료·다음 의도가 이후 여정 안내에 어떻게 반영되는지 보여준다.

정보 선정·안내 시점·기억 갱신의 세부 정책과 수용 기준은 GRD-Q16~Q18에서 정합니다.

### 독립 개발사 앱의 가치 제안

개발 전제는 **차량 기본 탑재 앱이 아닌 별도 개발사의 앱**입니다. 사람·장소·약속의 기억을 차량에 종속시키지 않고 이어 가며, 현재 여정에 맞는 질문과 정보로 돌려주는 방향을 제안합니다. 제조사만의 데이터 접근이나 모든 차종 지원을 전제하지 않습니다.

- **중심 경험 제안:** 재방문할 장소의 과거 동행 기억을 근거로 이번 동행 의도를 묻고, 답에 맞는 정보·약속을 제시합니다(UC-012 → UC-011). 실제 탑승 확인은 UC-006과 구분합니다.
- **연속성 확장 제안:** 지원되는 다른 차량에서도 본인의 허용한 기억을 이어 씁니다(UC-013). 사용자 식별·저장 방식·지원 환경·MVP 포함 여부는 GRD-Q20에서 검토합니다.
- **맥락 품질 제안:** 사용자가 안내 근거를 확인하고 잘못된 기억을 수정하거나 활용에서 제외해 후속 안내를 개선합니다(UC-014).

비교할 가치는 기능의 개수보다, 같은 장소에서도 개인의 기억과 이번 답에 따라 달라지는 질문·안내입니다. 제조사도 구현할 수 있는 기능이므로 이 방향의 경쟁력은 따로 검증해야 합니다.

## 문제

- "할머니가 가보고 싶다던 곳"은 채팅에, 가능한 날짜는 캘린더에, 함께한 장면은 사진첩에 흩어져 있습니다. 내비게이션에는 주소만 남습니다.
- 목적지는 저장되지만 그곳에 다시 갈 이유는 흩어집니다. 그래서 약속이 실행되지 않고, 다녀온 기억도 다음 여정으로 이어지지 않습니다.
- 이 불편을 직접 보여 주는 근거(인터뷰, 설문)는 아직 없습니다 → [GRD-Q9](OPEN_QUESTIONS.md)

## 타깃 (가설)

- 주 사용자: 가족 방문과 동행을 준비하는 운전자
- 참여자: 가족 구성원. 차량 앱을 설치하지 않고 공유 웹페이지로 참여합니다
- 규모와 근거: 미정 → [GRD-Q7](OPEN_QUESTIONS.md)

## Goals

| ID | 목표 | 심사 |
|---|---|---|
| GRD-G1 | 저장한 "다음 약속"(사람 + 장소)이 조율, 출발, 동행, 회고를 거쳐 실제 여정으로 완료되는 흐름을 처음부터 끝까지 보여준다 | `[차량특화]` `[창의]` |
| GRD-G2 | 차량이 여정의 관측과 실행을 맡는다. 차량 상태로 출발을 준비하고, 승인한 목적지·경유지를 내비게이션에 적용하고, 정차 중에 동행을 확인한다 | `[차량특화]` `[기술]` |
| GRD-G3 | 사용자가 승인한 범위 안에서만 실행하고, 관측(신호)과 해석(의미)을 구분해 신뢰를 지킨다 | `[차량특화]` `[창의]` |
| GRD-G4 | 다녀온 기억이 다음 여정 후보로 이어지는 반복 루프를 만들고, 이를 측정할 지표를 정한다 | `[사업]` |

> 핵심 결과물은 잘 쓴 일기보다 **실제로 함께 다녀온 하루**입니다. (draft §01)

## Non-goals

- 상시 녹음, 기록에 없는 대화나 감정 생성
- 가족관계 자동 추정, 전화번호로 위치 알아내기
- 비공개 채팅, 사진, 연락처 자동 읽기
- 주행 중 화면 조작 요구
- 출발 소식 자동 발송 (수신 동의, 발송 경로, 중복 방지를 검증한 뒤 확장)
- 명절 귀성, 공항 배웅, 가족 여행 시나리오 (같은 구조로 확장할 후속 시나리오)

## 대표 시나리오

**"이번 일요일, 할머니 모시고 저장해 둔 바다 카페에 다녀오기"**

| 단계 | 장면 | 차량과의 연결 |
|---|---|---|
| 1. 기억 | 지난 외출 때 정차 후 "할머니가 저 카페에 가보고 싶다고 하셨어"라고 남깁니다. 주변 장소 후보를 확인해 '할머니와 다음에 갈 곳'으로 저장합니다 | 위치, 음성 입력, 정차 상태 |
| 2. 조율 | 약속과 날짜로 여정 초안을 만듭니다. 가족은 공유 링크에서 시간과 후보를 고르고, 운전자가 승인합니다 | (차량 밖) |
| 3. 출발 | 날씨와 차량 상태를 갱신해 필요한 경유지를 제안합니다. 실제 출발을 확인한 뒤에 출발 소식 초안을 준비합니다 | 차량 상태, 내비게이션 |
| 4. 동행 | 정차 중 도어 신호로 탑승 후보를 감지하고, 누가 탔는지는 사용자에게 확인합니다. 승인한 동행 설정과 카페 경유 계획을 적용합니다 | 도어, (좌석), 공조, 경유지 |
| 5. 다녀옴 | 실제 이동과 확인한 방문으로 기록 초안을 만듭니다. 사진과 한마디를 더해 저장하고 약속을 완료합니다. 다음 여정 후보를 남깁니다 | 이동 기록 |

## 성공 기준 (데모, 초안)

- [ ] 대표 시나리오 5단계를 한 번의 흐름으로 시연한다
- [ ] 가족이 공유 페이지에서 고른 후보가 내비게이션 경유지에 반영되는 장면이 있다
- [ ] Virtual Console에서 바꾼 차량 상태가 앱의 출발 준비 안내에 반영된다
- [ ] 오판 방지: 문만 열기, 좌석에 짐 놓기, 경로만 탐색하기를 탑승, 방문, 출발로 확정하지 않는다
- [ ] 네트워크가 끊겨도 확정한 계획과 기록이 유지된다

(출처: draft §07 최종 데모, §08 공모전에서 보여줄 증거)

## 원칙

- **관측과 해석을 구분합니다.** 정차는 방문 확정이 아니고, 좌석 점유는 신원 확인이 아닙니다. 지연을 사고로 단정하지 않습니다.
- **AI는 계획을 돕고, 실행은 여정의 상태와 규칙을 따릅니다.** 생성한 문장이 그대로 차량 제어 명령이 되지 않습니다.
- **승인한 범위 안에서 실행합니다.** 경로, 공조, 전송을 각각 따로 승인합니다.
- 기억의 출처와 갱신 시각을 보존합니다. 공유 콘텐츠와 실행 명령을 분리합니다. 전송 중복을 막고 실행 결과를 확인합니다.

여정 상태: `제안 → 조율 → 확정 → 준비 → 이동 → 회고` (draft §04)

## 사업성 메모 (양식 6번 대비, 미정)

- 반복 사용 동인: 다녀온 기억이 다음 여정 후보가 됩니다
- 측정 후보 (draft §08): 기록 수정·완료율, 공유 응답률, 저장한 약속의 여정 전환율, 불필요한 확인 횟수
- 확장: 명절 귀성, 공항 배웅, 가족 여행
- 개인화 방향(검토): 운전자가 연결한 AI(Claude, ChatGPT, Gemini)가 가족 기억과 대한민국 명소발굴 (100×100)·관광 정보 후보 안에서 들를 곳을 정리. 보내는 범위는 최소, 실행은 운전자 승인([GRD-019~021](REQUIREMENTS.md))
- 제휴·수익 방향(검토): 공공 관광 데이터·지역 추천 목록과 연계한 "함께 갈 만한 곳", 지자체·관광 기관과의 가족 방문 캠페인, 제휴 장소는 제휴임을 밝히고 선택지로만 제안, 명절·장거리 이동 전 차량 점검 안내 연계
- 타깃 규모, 예상 MAU, Retention: **근거와 함께 작성 필요** → [GRD-Q7](OPEN_QUESTIONS.md)
- 내 AI 비용 구조: 요금은 사용자의 API 계정으로 청구되어 AI 기능이 늘어도 운영비가 함께 늘지 않음. 내 AI는 선택 기능(D-001)
