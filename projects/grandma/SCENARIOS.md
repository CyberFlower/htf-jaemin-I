# 다녀왔습니다: 기억이 다음 방문을 바꾸는 시나리오

상태: **Draft / 2026-11-14**. [기존 UC와 화면 흐름](USE_CASES.md)을 설명하는 자료이며 Goal·FR·Decisions의 상태나 우선순위를 변경하지 않습니다. PR #2의 제출용 장면 원본은 [SCENARIO.md](SCENARIO.md)입니다. 이 문서는 재방문 변형과 구현 경계를 설명하며 별도의 제출 장면 순서를 정의하지 않습니다.

## 1. 보여주려는 가치

**같은 목적지를 골라도, 누구와 가는지와 지난 경험에 따라 들를 곳과 추천 이유가 달라진다. 다녀온 뒤 확인한 경험은 다음 질문으로 이어진다.**

외부 서비스는 장소와 주제별 발견의 재료를 제공한다. 우리 앱은 그 재료에 이번 동행·원하는 경험·과거 방문을 연결하고, 사용자가 선택한 곳을 차량 여정으로 이어 준다. 관계명만으로 나이·취향·보행 능력을 추정하지 않는다.

## 3. 대표 장면: 같은 카페, 이번에도 어머니와

설명용 장소는 목업의 가상 장소다. ‘파도 서가’ 등의 이름에 실제 100×100 선정 여부를 붙이지 않는다. 사용자는 조용한 분위기와 바다 전망을 좋아한다고 직접 설정했고, 어머니는 걷기 편한 곳을 선호한다고 확인한 상황이다.

| 장면 | 사용자가 보는 것·하는 일 | 서비스의 판단·변화 | 연결 |
|---|---|---|---|
| A. 지난 기억 | 지난번 어머니와 방문한 카페를 다시 선택한다 | 장소가 같은지 확인하고 활용을 허용한 방문을 찾는다. 단순히 같은 해변에 있다는 이유로 같은 가게라고 판단하지 않는다 | UC-012 B1, UC-014 |
| B. 이번 동행 | “지난번 어머니와 다녀온 곳이에요. 이번에도 함께 가시나요?”에 함께/혼자/미정으로 답한다 | 이번 동행 **예정**만 바뀐다. 과거 기록과 실제 탑승은 바꾸지 않는다 | UC-012 B2~B4 |
| C. 들를 곳 | 여정 계획에서 “근처에 들를 곳”을 연다 | 목적지 좌표를 기준으로 카페·음식점 후보를 검색하고, 명시한 취향·동행 선호·이용 가능한 장소 지식을 연결한다 | UC-003·011, 목업 후보 UC-018 |
| D. 두 후보 비교 | 다녀온 카페와 새 음식점을 큰 카드로 비교한다 | 카드에는 방문 표시와 이유 한 줄. 출처·확인 필요 정보는 상세에서 연다. ‘100×100에서 찾은 곳’ 표시는 목록·권리·장소 일치가 확인된 경우만 사용한다 | 목업 후보 UC-016·017·018 |
| E. 선택과 실행 | 장소를 여정에 담고, 목적지·경유 순서를 확인한 뒤 내비 적용을 승인한다 | 담기는 후보 저장. 내비 적용은 별도 요청이며 콜백과 현재 경로 확인 전에는 성공으로 표시하지 않는다 | UC-005, GRD-005·007 |
| F. 이동 | 필요한 안내 한 줄만 듣는다 | 터치·입력을 요구하지 않는다. 개인 기억을 동승자 앞에서 읽을지는 별도 공개 설정을 따른다 | GRD-N01, UC-011, GRD-Q19 |
| G. 다녀온 뒤 | 정차 후 날짜 → 실제 동행 → 선택 문구 또는 음성 → 최종 확인 | 위치 근접·경유지 도착은 방문 후보일 뿐이다. 사용자가 확인한 뒤 방문과 스탬프를 기록한다. 음성 문장 채택만으로 저장하지 않는다 | UC-008, 목업 후보 UC-016 |
| H. 다음번 | 다시 장소를 선택한다 | 저장한 방문·동행이 다음 질문의 근거가 된다. 다른 동행을 답하거나 잘못된 기억을 수정하면 안내도 달라진다 | UC-012·014 |

### 같은 목적지에서 달라지는 답

| 이번 답 | 제안하는 처리 | 사용자에게 보이는 표현 예 |
|---|---|---|
| 어머니와 함께 | 확인된 동행 선호를 함께 적용 | “어머니가 걷기 편한 곳을 찾으셔서” — 해당 장소의 보행 정보가 확인됐을 때만 |
| 오늘은 혼자 | 어머니 선호를 적용하지 않음 | “조용한 곳을 좋아하셔서” |
| 아직 미정 | 동행 선호를 확정하지 않음 | “목적지 가까이에서 찾았어요” 또는 본인 취향에 근거한 설명 |
| 새로운 곳 먼저 | 이미 다녀온 곳임을 보존하면서 탐색 순서를 바꿈 | “새로운 곳”과 “✓ 다녀온 곳”을 구분 |
| 외부 속성이 오래됐거나 없음 | 미확인 조건으로 적합성을 보장하지 않음 | “주차 정보는 아직 확인하지 못했어요” |

## 4. 100×100을 쓰는 두 번째 장면: 관심사에서 새 장소로

‘다음에는 지역 빵집에 들르고 싶다’고 사용자가 관심사를 선택한다. 이용 조건이 확인된 100×100의 해당 주제 목록에서 목적지 권역의 장소를 찾고, 외부 장소 검색으로 주소·좌표·지점을 확인한다. 같은 곳을 중복 추천하지 않도록 통합한 뒤 이번 동행 조건에 맞는 후보를 제시한다.

목록에 올랐다는 사실은 발견 근거다. 현재 영업 여부, 조용함, 주차 편의나 동행 적합성을 보증하지 않는다. 방문 스탬프는 해당 장소를 실제로 다녀왔다고 확인했을 때만 남기고, 한 번 방문한 장소가 여러 주제에 속해도 방문 횟수를 늘리지 않는다. 주제별 탐험 진행률은 목록 판본과 고유 장소 집합이 확보된 다음 확장한다.

100×100 제공 경로가 미확정이어도 카카오 Local·TourAPI와 개인 기억으로 기본 추천을 제공할 수 있다. 실제 연결 전에는 ‘100×100 연동 예정’이라는 설명 자료로만 보여주고, 가상 장소를 실제 선정 장소처럼 시연하지 않는다.

## 5. 현재 HTML로 따라 하는 시연

실행: [journey-demo.html](../../spikes/grandma-journey-context/journey-demo.html). 시연 데이터 초기화는 기존 개인 데모 변경을 지우므로 필요할 때만 한다.

1. 홈의 ‘여정 준비’에서 초기 목적지 ‘파도 서가’를 확인한다. 동일 장소의 어머니와의 방문 기록으로 질문이 나오고, ‘모래빛 식탁’으로 목적지를 바꾸면 나오지 않는 것을 비교한다.
2. 다시 ‘파도 서가’를 선택해 ‘함께 가요 / 혼자 가요’를 비교한다. 추천 화면에는 두 장만 표시하고, 예정 동행에 따라 이유가 달라진다.
3. 음식점·방문지 등 경유 후보를 두 곳까지 담는다. ‘담은 곳’에서 순서와 마지막 목적지를 확인한다. 적용 승인 전에는 아무 내비 상태도 바뀌지 않는다.
4. ‘이 여정으로 적용 · 시연’을 눌러 확인 중 → 성공을 본다. 취소하거나 시연 설정에서 실패를 선택하면 성공으로 바뀌지 않는다. 방문 스탬프는 그대로다.
5. 홈에서 ‘여정 마치기’ → ‘다녀온 곳 선택’을 누른다. 날짜·실제 동행·한마디·최종 확인을 거친 뒤에만 스탬프가 늘어난다. 음성 문장은 마이크 없이 시연하며, 채택만으로 저장하지 않는다.
6. 발자국에서 수정·활용 제외·삭제를 비교한다. ‘다시 가기’는 해당 장소를 다음 목적지로 선택한다. 최근 활용 가능한 기록의 동행을 질문하며, 다른 장소의 기억은 사용하지 않는다.
7. 주제를 골라 예시 장소를 좁힌다. 100×100 선정 목록이 아님을 확인한다. 상세의 정보 출처에서 장소 예시와 개인 방문 기록을 구분한다.
8. 시연 설정에서 검색 실패를 선택하면 저장된 방문 장소만 표시한다. 방문한 곳이 없는 권역에서는 빈 결과를 표시한다. 주행 또는 차량 상태 확인 불가에서는 조작을 차단하고 정차 시연으로 복귀한다.

현재 목업은 **내부 장소 ID가 같은 기록**으로 재방문 질문을 구현한다. 외부 제공처 간 장소 매칭은 구현하지 않았으며 [장소 식별 설계](PLACE-INTEGRATION.md)의 검증이 필요하다. 주변 검색은 여전히 권역별 가상 데이터다. 내비·음성·차량 상태·날씨·외부 검색 결과는 시연이며 실제 SDK 호출이나 인식 결과가 아니다. 홈은 위 대표 여정의 최소 흐름이며 UC-015의 약속·도어 이벤트 등 전체 카드 우선순위를 구현하지 않는다.

## 6. 실패 장면도 함께 설명한다

| 조건 | 기대 동작 / 검증할 것 |
|---|---|
| 위치 권한 거부·오래된 위치 | 사용자가 선택한 목적지를 사용. 과거 위치를 현재 위치라고 표시하지 않음 |
| 같은 이름의 다른 지점 | 자동으로 기억을 합치지 않고 지점 선택. 무관한 과거 동행을 노출하지 않음 |
| 검색 실패·호출 제한 | 사용 가능한 출처 결과만 표시하고 누락을 알림. 확정 계획·개인 방문은 보존 |
| 내비 적용 시간 초과 | ‘적용 확인 중/실패’로 남김. 재시도 전 현재 목적지·경유지를 조회해 중복 추가 방지 |
| 음성 실패·취소 | 큰 선택 버튼으로 돌아감. 확인하지 않은 인식문은 기록하지 않음 |
| 주행 제한 상태 미확인 | 현재 UC-015 E2의 보수적 기본값 유지. 위치가 안 움직인다는 이유로 조작을 열지 않음 |

## 7. 후속 검증과 범위

[API 채용안](API-ADOPTION.md)의 에뮬레이터 실험과 [외부 장소 연계안](PLACE-INTEGRATION.md)의 한 권역 데이터 실험을 먼저 수행한다. 추천을 선택하는 데 걸리는 시간, 오터치, 동일 장소 오매칭, 추천 이유의 출처 확인 가능 여부를 관찰한다. 목표 수치와 사용성 효과는 아직 검증하지 않았다.

가족 공유·공조·다른 차량에서의 기억 연속성은 기존 UC의 확장으로 유지한다. 이 시나리오 자료에서 기존 P0/P1/P2를 재지정하지 않는다. 홈과 추천 상세의 통합 순서는 GRD-Q26에서 검토한다.
