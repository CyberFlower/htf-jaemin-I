# SCENARIO: 다녀왔습니다 (`GRD`)

> 코어 시나리오 가이드입니다. 대표 시나리오를 장면 단위로 처음부터 끝까지 설명합니다.
> 상태: **Draft**. 원천은 [GOAL.md](GOAL.md), [USE_CASES.md](USE_CASES.md), [REQUIREMENTS.md](REQUIREMENTS.md)입니다.

## 1. 한눈에 보기

- 시나리오 이름: 이번 일요일, 할머니 모시고 저장해 둔 바다 카페에 다녀오기
- 누가: 가족 방문과 동행을 준비하는 운전자 (가설, [GOAL.md](GOAL.md) 타깃)
- 언제·어디서: 지난 외출의 정차 중부터 일요일 귀가 후 주차까지. 동선은 집 → 할머니 댁(탑승) → 바다 카페 → 귀가
- 얻는 것: 저장한 "다음 약속"이 실제로 함께 다녀온 하루가 되고, 그 기록이 다음 약속으로 이어집니다
- 화면 규격: 1920×1080 (실험 목업 기준. 에뮬레이터 실측 전, [Q4](../../docs/open-questions.md))
- 전체 길이: 약 150초 (6절 콘티 제안)

## 3. 장면별 상세

### SC-01 기억

- 상황: 지난 외출 때 카페 앞에 정차한 운전자. 함께 탄 할머니가 "저 카페 가보고 싶다"고 말한 직후입니다.
- 사용자 행동: 홈(S01)의 🎙 기억 남기기를 직접 눌러 "할머니가 저 카페 가보고 싶대"라고 말합니다. 주변 후보 중 바다 카페를 고르고 함께 갈 사람으로 할머니를 고릅니다(GRD-UC-002 B1~B3).
- 앱 응답: 한마디를 텍스트로 받고, 현재 위치 주변의 장소 후보를 보여 줍니다. 사용자가 확인한 장소만 '할머니와 다음에 갈 곳' 약속 카드(S03)로 저장합니다.
- 차량 신호·SDK: SpeechToText — 문서 확인, FusedLocation `getLastKnownLocation` (FUSED_LOCATION) — 문서 확인, 장소 검색 외부 API — 확인 필요 (GRD-Q5), 주행/정차 판단 — 확인 필요 (Q8)
- 오판 방지·대체 동작: 상시 녹음 없이 사용자가 시작할 때만 듣습니다. 주행 중이면 입력을 정차 후로 미룹니다(E1). 위치나 후보를 얻지 못하면 확인할 수 없는 장소를 저장하지 않습니다(E2, 대체 방법은 GRD-Q14). 음성 대신 텍스트로도 입력합니다(A1).
- 화면: 위쪽 실에 지난 기억 사진 두 장(어머니와 함께한 뒷모습)과 "?" 빈 사진틀이 걸리고, 빈 사진틀 위에 운전자의 빛이 있습니다. 오른쪽 끝에는 빈 "다음 약속" 꼬리표. 아래에 "남길 기억이 있나요?"와 `기억 남기기`.
- 시연 방법: [목업](../../spikes/grandma-journey-context/README.md) `#SC-01`: 지금 카드 `기억 남기기` → 마이크(음성 시연) → `이대로 쓰기` → 바다 카페 → 할머니 → `약속 저장`
- 캡처·영상: 캡처 [SC-01.png](assets/scenes/SC-01.png)

### SC-02 조율·확정

- 상황: 정차 중, 저장한 약속으로 이번 일요일 여정을 만듭니다.
- 사용자 행동: 약속 카드에서 [여정 만들기] → 일요일 10:30을 고르고, 날씨·장소 정보를 검토한 뒤 경로·공조·전송을 각각 체크해 승인합니다(GRD-UC-003 B1~B3).
- 앱 응답: 약속의 사람·장소로 동행자·목적지·경유지·시간 초안(S04)을 만들고, 날씨·장소 정보를 출처와 조회 시각과 함께 보여 줍니다. 승인 화면(S06)은 적용할 작업을 따로 보여 줍니다.
- 차량 신호·SDK: 날씨·장소 외부 API — 확인 필요 (GRD-Q5). 승인 자체는 의존 없음(GRD-005)
- 오판 방지·대체 동작: 정보가 없으면 "미확인"으로 표시하고 추측하지 않으며 수동 계획으로 진행합니다(A1, GRD-N03). 승인하지 않으면 차량 실행과 외부 전송을 하지 않습니다(E1). 가족 응답(GRD-004)을 넣을지는 GRD-Q1, GRD-Q15.
- 화면: 약속 상세는 손글씨 꼬리표("할머니가 저 카페 가보고 싶대")와 할머니 얼굴 서명, 함께 갈 사람·상태, 오른쪽의 바다 카페 사진. 아래에 `여정 만들기`.
- 시연 방법: 목업 `#SC-02`: 약속 상세의 `여정 만들기` → 이번 일요일·10:30 → `승인할 작업 확인` → 경로 체크 → `계획 확정`. 주차 "미확인", 공조 "지원 여부 미확인"을 보여 줍니다. 확정하면 시연 시각이 일요일 아침(10:02, 집)으로 넘어갑니다
- 캡처·영상: 캡처 [SC-02.png](assets/scenes/SC-02.png)

### SC-03 출발

- 상황: 일요일, 집에서 시동을 건 차 안. 홈에 오늘 여정 카드가 있습니다.
- 사용자 행동: 오늘 여정 카드의 [준비 점검]을 누르고, 제안된 경유를 확인한 뒤 1구간(집 → 할머니 댁) 경로 적용을 승인합니다(GRD-UC-005 B1~B3).
- 앱 응답: 연료 또는 배터리 상태와 날씨를 새로 조회해 필요한 경유를 제안하고(S07), 승인한 경로를 내비게이션에 요청한 뒤 콜백으로 적용 결과를 알려 줍니다.
- 차량 신호·SDK: Vehicle Fuel / EvBattery (CAR_ENERGY) — 문서 확인, NaviHelper `requestRouteWithWaypoints()` / `addWaypoint()` (NAVI_ROUTE_SEARCH) — 문서 확인, 에뮬레이터 동작 — 확인 필요 (GRD-Q3)
- 오판 방지·대체 동작: 잔량만으로 도착 가능 여부를 단정하지 않고, 지원하지 않는 상태는 "확인 불가"로 표시합니다(A1). 화면에 계획을 보여 주는 것으로 내비 적용을 대신하지 않고, 적용에 실패하면 알립니다(E1). 같은 요청을 다시 보내도 한 번만 실행합니다(GRD-N05).
- 화면: 실에 오늘 동선(집 → 할머니 댁 → 바다 카페 → 집)이 보이고, 운전자의 빛은 집에, 약속 꼬리표는 바다 카페 옆에 걸려 있습니다. 아래에 오늘 일정, 연료·날씨, `준비 점검`.
- 시연 방법: 목업 `#SC-03`: 지금 카드 `준비 점검` → `경유 추가` → `1구간 경로 적용`. 시연 도구의 내비 응답을 `실패`로 바꾸면 "계획은 그대로" 상태를 보여 줍니다. 연료 20/40/80%로 경유 제안을 비교합니다
- 캡처·영상: 캡처 [SC-03.png](assets/scenes/SC-03.png)

### SC-04 주행 (1구간)

- 상황: 집에서 할머니 댁으로 가는 1구간 주행 중.
- 사용자 행동: 없음. 화면을 누르지 않습니다.
- 앱 응답: 홈 대신 주행 모드(S09)로 바뀌어 다음 목적지와 안내 한 줄만 크게 보여 주고, "할머니 댁까지 20분"(예시)처럼 음성으로 안내합니다.
- 차량 신호·SDK: 주행/정차 판단 — 확인 필요 (Q8, Q11), TextToSpeech — 문서 확인
- 오판 방지·대체 동작: 주행/정차를 판단할 수 없으면 주행 중으로 간주하는 안이 제안되어 있습니다(GRD-UC-015 E2, GRD-Q22). 확인이나 입력이 필요한 일은 정차 후로 미룹니다(GRD-N01).
- 화면: 어두운 배경에 실이 전구 줄처럼 빛나고, 운전자의 빛이 할머니 댁으로 가는 중입니다. 큰 글씨 "할머니 댁까지 20분"과 음성 안내 한 줄. 버튼 없음.
- 시연 방법: 목업 `#SC-04` 또는 시연 도구 `D 주행`. 화면을 눌러도 반응하지 않습니다
- 캡처·영상: 캡처 [SC-04.png](assets/scenes/SC-04.png)

### SC-05 동행

- 상황: 할머니 댁 앞에 정차. 도어가 열렸다 닫힌 것을 관측했습니다.
- 사용자 행동: 홈의 탑승 후보 카드 "할머니와 함께 출발하시나요?"에 [네]를 누르고, 2구간(할머니 댁 → 바다 카페) 경로 적용을 승인합니다(GRD-UC-006 B1~B2, GRD-UC-005 B2).
- 앱 응답: 관측 근거(도어 열림·닫힘)와 함께 동행을 묻고(S08), 사용자가 확인한 동행자를 이번 여정에 설정한 뒤 2구간 경로를 적용합니다. 공조 적용은 지원할 때만, 따로 승인합니다(GRD-UC-007, P2).
- 차량 신호·SDK: Vehicle Door (CAR_DOORS) — 문서 확인, Seat 좌석 점유 `getCurrentSeatOccupancy`·`registerSeatOccupancy` (CAR_SEATS) — API 이름 문서 확인, 값의 의미·에뮬레이터 동작 확인 필요 (GRD-Q2), NaviHelper `requestRouteWithWaypoints()` (NAVI_ROUTE_SEARCH) — 문서 확인
- 오판 방지·대체 동작: 문만 열고 닫았거나 좌석에 짐을 놓은 것을 탑승이나 신원으로 확정하지 않습니다(E1, GRD-N02). 좌석 신호를 쓸 수 없으면 사용자가 동행자를 직접 고릅니다(A1). 답하지 않으면 미확인으로 둡니다.
- 화면: 할머니 댁에서 운전자의 빛 옆에 할머니 자리가 흐린 얼굴의 점선 원("할머니?")으로 기다립니다. 아래에 "할머니와 함께 출발하시나요?", 도어 관측 근거, `확인하기` `나중에`. 운전자가 `네, 함께 가요`를 눌러야 할머니의 빛이 채워집니다.
- 시연 방법: 목업 `#SC-05`: 지금 카드 `확인하기` → `네, 함께 가요` → `2구간 경로 적용`. 처음부터 이어 갈 때는 `P` 뒤 시연 도구의 `도어 열림 → 닫힘`
- 캡처·영상: 캡처 [SC-05.png](assets/scenes/SC-05.png)

### SC-06 주행 (2구간)

- 상황: 할머니와 함께 바다 카페로 가는 2구간 주행 중.
- 사용자 행동: 없음.
- 앱 응답: 주행 모드(S09)에서 "바다 카페까지 25분. 할머니가 가보고 싶다고 하신 곳이에요."(예시)처럼 남은 시간과 약속의 맥락을 음성으로 안내합니다.
- 차량 신호·SDK: TextToSpeech — 문서 확인, 주행/정차 판단 — 확인 필요 (Q8, Q11)
- 오판 방지·대체 동작: 화면 조작을 요구하지 않습니다(GRD-N01). 동승자가 듣는 자리에서 개인 기억을 어디까지 말할지는 정하지 않았습니다(GRD-Q19). 맥락 안내 자체의 FR은 아직 없습니다(GRD-UC-011, GRD-Q16·Q17).
- 화면: 어두운 배경에서 운전자의 빛과 할머니의 빛(얼굴)이 나란히 바다 카페 꼬리표 쪽으로 갑니다. "바다 카페까지 25분"과 음성 안내 한 줄. 버튼 없음.
- 시연 방법: 목업 `#SC-06` 또는 시연 도구 `D 주행`(2구간)
- 캡처·영상: 캡처 [SC-06.png](assets/scenes/SC-06.png)

### SC-07 다녀옴

- 상황: 바다 카페를 거쳐 귀가한 뒤 주차한 차 안.
- 사용자 행동: 홈의 귀가 카드 "바다 카페에 다녀오셨나요?"에서 [기록하기]를 누르고, 방문을 확인한 뒤 한마디를 더해 저장합니다. 이어서 다음 약속을 남깁니다(GRD-UC-008 B1~B3, A1).
- 앱 응답: 실제 이동과 사용자가 확인한 방문으로 기록 초안(S10)을 만들고, 저장하면 약속을 완료로 바꿉니다. 다음 약속은 SC-01과 같은 흐름(GRD-UC-002)으로 이어집니다.
- 차량 신호·SDK: 이동 기록 (FusedLocation) — 문서 확인, 기록 음성 SpeechToText (STT_SERVICE) — 문서 확인, 한국어 인식 — 확인 필요 (GRD-Q6)
- 오판 방지·대체 동작: 정차만 관측된 것을 방문으로 확정하지 않습니다(E1, GRD-N02). 기록에 없는 대화나 감정을 만들어 넣지 않고, 사진은 사용자가 고른 것만 넣습니다(GRD-010). 최종 확인 전에는 기록을 만들지 않고, 키보드 없이 선택과 음성으로 남깁니다(GRD-016). 사진 고르는 방법과 기록 범위는 GRD-Q12, 저장 실패 처리는 GRD-Q14.
- 화면: 두 빛이 집에 돌아와 있고 약속 꼬리표는 아직 걸려 있습니다. 아래에 "바다 카페에 다녀오셨나요?", 머문 시간(관측일 뿐), `기록하기` `나중에`.
- 시연 방법: 목업 `#SC-07`: 지금 카드 `기록하기` → `네, 다녀왔어요` → 날짜 → 할머니 → 한마디 → `확인하고 저장` → 약속 완료. 저장하면 홈이 SC-08의 재방문 카드로 이어집니다
- 캡처·영상: 캡처 [SC-07.png](assets/scenes/SC-07.png)

### SC-08 다시 가는 여정

- 상황: 과거 어머니와 방문한 가상 장소 ‘파도 서가’를 다시 선택합니다. 첫 방문의 할머니 사례와 구분한 재방문 변형입니다.
- 사용자 행동: 홈 ‘여정 준비’ → 이번 동행 선택 → 추천 두 곳 비교 → 경유 후보 최대 두 곳 담기 → 내비 적용 승인 시연 → 여정 마치기 → 실제 방문 기록.
- 앱 응답: 내부 장소 ID가 같은 최근 활용 가능 방문을 찾습니다. 답에 따라 명시한 동행 선호를 적용하며 기록은 최종 저장 후 생성합니다.
- 차량 신호·SDK: 현재는 로컬 시연입니다. 실제 NaviHelper·STT·차량 제한 상태를 읽지 않습니다. 실제 앱에서 쓸 API는 [SDK.md](SDK.md) 2절 SC-08 행(NaviHelper `getDestinationInfo()` → `onDestinationInfo`, FusedLocation, SpeechToText, 경로 적용)이고, 검증 계획은 [API-ADOPTION.md](API-ADOPTION.md)를 따릅니다.
- 오판 방지·대체 동작: 다른 장소의 동행 기억을 질문하지 않습니다. 예정 동행과 실제 방문 동행을 분리합니다. 담기·내비 성공 시연·여정 종료로 스탬프를 만들지 않습니다. 검색 실패·내비 실패/취소·상태 미확인 입력 제한을 시연 설정에서 비교합니다.
- 화면: 실에 사진 세 장이 걸리고, 가장 최근의 바다 카페 사진에는 할머니와 나란히 선 뒷모습이, 그 옆 실에는 매듭이 있습니다. 이어서 "오늘" 빛과 빈 "다음 약속" 꼬리표. 아래에 "파도 서가에 가볼까요?"와 `여정 준비`.
- 시연 방법: 목업 `#SC-08`(첫 방문 기록을 마친 상태)에서 [시연 순서](SCENARIOS.md#5-현재-html로-따라-하는-시연)를 따릅니다. 틀에서는 `embed=1`로 시연 도구·테두리를 숨깁니다. 검색 실패·내비 실패·상태 확인 불가는 오른쪽 시연 도구에서 바꿉니다.
- 캡처·영상: 캡처 [SC-08.png](assets/scenes/SC-08.png)

## 6. 영상 콘티 (제안)
