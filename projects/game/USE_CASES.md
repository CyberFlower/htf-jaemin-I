게임 구조:

| 항목 | 내용 |
|---|---|
| 재화 | 건축 자재(희소. 운행 거리·안전운전 일일 항목·돌발 퀘스트 → 새 도시 열기, 시설 짓기, 업그레이드 단계 돌파), 골드(완성품 거두기 → 시설 업그레이드, 상점 GAM-033). [DECISIONS.md](DECISIONS.md) D-003, [SCREENS.md](SCREENS.md) 3절 |
| 운행 보상 | 주차할 때마다 택배가 온다. 거리 자재와 그날 새로 달성한 안전운전 항목의 자재가 한 카드에 담긴다 |
| 일일 퀘스트 | 일정 시간 이상 운전, 급가속·급감속 없이 운전, 급제동 없이 운전, 방향 지시등 사용(GAM-026~029) |
| 돌발 퀘스트 | 장거리 휴식, 정비 시기(기록으로 완료), 차량이 확인하는 관리 항목(신호로 완료, GAM-048). 완료하면 자재 |
| 하루 행동 제한 | 쓰다듬기는 횟수 충전(최대 3회), 생산은 시간과 상한으로 제한 |

공통 적용:

- 차량 화면 조작은 주차가 확인된 상태에서만 합니다(GAM-N01). 주행 중에는 짧은 음성 안내만 씁니다.
- 실제 차량 경고가 있으면 퀘스트 안내보다 먼저 또는 함께 보여줍니다(GAM-N02).
- 주행이 시작되면 열린 창을 닫고 확정하지 않은 조작(짓기, 구매, 배치)은 취소합니다. 자원은 차감하지 않고, 생산과 쓰다듬기 충전은 계속됩니다(GAM-N01, GAM-020).
- 운전 행동 퀘스트는 주행 중 피드백과 불이익을 주지 않습니다(GAM-N06). 미달성은 "보상 없음"일 뿐 감점이 아닙니다.
- 신호는 차량의 관측값입니다. 누가 운전했는지 구분하지 않고, "안전하게 운전했다"고 단정하지 않습니다.
- 관련 FR의 수용 기준·검증 태그가 상세 정책의 원천입니다. UC에는 SDK 검증 완료를 새로 주장하지 않습니다.

확장 (GAM-UC-007~010, 2026-11-14 제안):

- 섬 하나를 전국 지도의 여러 도시로 넓힙니다. 지금의 섬은 본거지(첫 도시)가 되고, GAM-UC-001~004는 본거지에서 그대로 동작합니다.
- 재화 역할은 [DECISIONS.md](DECISIONS.md) D-003을 따릅니다.

| 재화 | 역할 | 얻는 곳 | 쓰는 곳 | 조작하는 곳 |
|---|---|---|---|---|
| 건축 자재 | 희소 | 차에서만: 운행 거리, 안전운전 일일 항목, 돌발 퀘스트 | 새 도시 열기, 새 시설 짓기, 업그레이드 단계 돌파 | 차량 화면(주차 중) |
| 골드 | 흔함 | 시설 자동 생산 | 시설 업그레이드, 장식 | 차량 화면(주차 중), 폰 |

- 퀘스트는 차량 신호로 자동 진행합니다. 폰에서는 진행하거나 완료할 수 없습니다(GAM-046).
- 지도는 대한민국 전체를 덮습니다([DECISIONS.md](DECISIONS.md) D-004).
- 운행 거리로 얻는 자재는 주 단위로 완만하게 줄어듭니다. 수식 제안은 GAM-001에 있습니다(GAM-Q27).
- 폰 연동(GAM-UC-010)은 공모전 심사 대상인 Pleos Connect 앱 밖의 확장입니다. 확대 계획(P2)으로 두고 1차 목업에는 폰 화면 한 장면만 넣습니다(D-004).

Goal과의 관계: [GOAL.md](GOAL.md)에는 안전운전 퀘스트를 직접 다루는 Goal이 없습니다. 퀘스트 확장 틀(GAM-G4), 반복 루프(GAM-G5), 원칙 "안전·친환경과 부딪히지 않는 보상"에 연결했습니다. 연료 보상 대신 안전운전 보상을 쓰자는 안([GAM-Q6](OPEN_QUESTIONS.md))과도 이어집니다. GOAL의 퀘스트 구조 표에 일일·돌발 퀘스트를 넣을지는 팀이 정합니다. 2026-11-14에 추가한 운전 경험 퀘스트(GAM-UC-005 동승·안전벨트, GAM-UC-006 도로 주의 구간)도 퀘스트 확장 틀(GAM-G4)에 연결한 제안이며, 퀘스트 구조 표에 출처로 넣을지는 팀이 정합니다.

관련 결정: 아래 미결정의 `GAM-Q#`는 [프로젝트 질문](OPEN_QUESTIONS.md), `공통 Q#`는 [저장소 질문](../../docs/open-questions.md)을 참조합니다.

## GAM-UC-001 운행 후 택배로 보상 받기 (거리 자재, 안전운전 자재)

- 상태: Draft
- 목표: GAM-G4, GAM-G5
- 주 행위자: 운전자
- 보조 행위자: 차량(Odometer 누적 거리·트립 시간, Brake 페달, TurnSignal, AAOS 차량 속도 `PERF_VEHICLE_SPEED`, 주차 판단 신호), Android 권한 시스템(속도 권한 동의 창)
- 사용자 목표: 운행할 때마다 달린 거리만큼 자재를 받고, 평소 운전을 조금 더 안전하게 하고, 그 결과가 매일 도시 보상으로 이어지는 것을 확인하기. 항목은 평소 운전으로 어렵지 않게 완수할 수 있어야 한다
- 범위: 운행 거리 자재 계산, 일일 퀘스트 발급·초기화, 운행 중 신호 관측, 주차 후 판정, 택배 카드 표시, 자재 적립. 자재로 시설을 짓는 것은 GAM-UC-003, 도시를 여는 것은 GAM-UC-008이 맡는다
- 트리거: 하루가 바뀐 뒤 운전자가 운행을 시작하거나 주차 중에 앱을 연다
- 사전 조건: 오늘의 일일 퀘스트가 발급되어 있다(GAM-024). 운행 중 앱이 화면에 없어도 신호를 받을 수 있다(확인 필요, GAM-Q25)
- 성공 후 조건: 이번 운행의 거리 자재와 새로 달성한 항목의 자재가 한 번만 적립되어 저장된다. 항목별 달성·미달성·판정 불가 상태와 근거가 저장된다
- 실패·취소 후 조건: 판정할 수 없는 항목은 "판정 불가"로 두고 보상을 주지 않는다. 미달성 항목 때문에 기존 자원이나 도시가 줄지 않는다
- 관련 결정: [DECISIONS.md](DECISIONS.md) D-003(일일 항목 보상은 자재)
- 미결정: GAM-Q20(Odometer 없을 때 표시), GAM-Q27(운행 자재 주간 상한, 수식 제안은 GAM-001), GAM-Q21(운영 규칙·기준값), GAM-Q22(운전 시간 항목의 부작용), GAM-Q23(급가속·급감속·급제동 판정 기준과 속도 시연), GAM-Q24(방향 지시등 판정 기준), GAM-Q25(백그라운드 신호 수집), GAM-Q1·공통 Q8(주차·주행 판단), 공통 Q6(AAOS 권한 승인), GAM-Q2(Virtual Console 시연)
- 출처: 2026-11-13 팀 논의(일일 퀘스트 항목 4종), 2026-11-14 팀 논의, [SCREENS.md](SCREENS.md) S03, [GOAL.md](GOAL.md) 원칙, [GAM-Q6](OPEN_QUESTIONS.md)

### 실행 환경·제약

- 주행·정차: 퀘스트 화면 조작은 주차 중에만 한다. 주행·주차 판단은 확인 필요 — GAM-Q1, 공통 Q8
- 차량 신호:
  - 트립 시간(Odometer)과 브레이크 페달(Brake)은 문서 확인 수준이다
  - TurnSignal은 `getCurrentTurnSignalState`와 상태 콜백으로 읽는다(문서 확인)
  - **속도는 Vehicle SDK에 없고, AAOS `CarPropertyManager`의 `PERF_VEHICLE_SPEED`로 읽는다**(Pleos 차량 앱 FAQ, [dev-environment.md](../../docs/contest/dev-environment.md) 4.3절). 가속도는 프로퍼티가 없어서 속도 변화로 계산한다
  - 주차·주행 판단 후보: AAOS `GEAR_SELECTION`(P단), `PARKING_BRAKE_ON`, `CarUxRestrictionsManager`(4.3절). 어떤 조합을 쓸지는 GAM-Q1, 공통 Q8
  - 에뮬레이터 동작은 미검증이다. Virtual Console에는 속도 항목이 없어서 속도를 바꿔 시연하는 방법을 확인해야 한다 — GAM-Q23, GAM-Q2
- 속도 권한: `Car.PERMISSION_SPEED`는 Dangerous 권한이다. 설치만으로 받을 수 없고 실행 중 사용자 동의가 필요하다
  - 동의 창은 화면 조작이 필요하므로 주차 중에만 띄운다(A5, GAM-N01)
  - 거부해도 앱은 동작한다. 속도를 쓰는 두 항목만 "판정 불가"가 된다(E1)
  - 설정에서 언제든 회수될 수 있으므로 운행을 시작할 때마다 권한을 확인한다
  - AAOS 권한도 App Market·공모전 사전 승인 대상인지는 확인 필요 — 공통 Q6
- 판정 원칙: 급제동은 위험을 피한 결과일 수 있다. 항목은 "시간당 n회 미만"처럼 여유 있게 두고, 미달성에 불이익을 주지 않는다(GAM-N06)
- 운전 시간 항목은 운전을 늘리는 동기가 될 수 있다. 평소 운행으로 채울 수 있는 기준인지 검토한다 — GAM-Q22, GAM-N03
- 네트워크·외부 전송: 해당 없음. 기록과 판정은 로컬에서 한다

## GAM-UC-002 돌발 퀘스트 처리하기 (장거리 휴식, 정비 시기)

- 상태: Draft
- 목표: GAM-G2, GAM-G4
- 주 행위자: 운전자
- 보조 행위자: 차량(Odometer 트립 시간·누적 거리, 주차 판단 신호, Safety의 오일·브레이크액 레벨과 워셔액 경고), TextToSpeech
- 사용자 목표: 오래 운전할 때 쉬어 갈 시점을 알고, 정비 시기가 오면 알아차리기. 대응하면 자재도 받기
- 범위: 연속 운전 시간 관측, 돌발 퀘스트 생성과 음성 안내, 주차 시간으로 완료 판정, 보상 적립. 정비 시기 돌발 퀘스트는 대안 흐름 A4~A6, 차량이 스스로 확인하는 관리 항목은 A7~A8이다. 정비 기준 계산은 GAM-006, 기록과 다음 주기는 GAM-007이 맡는다. 휴게소 경로 제안·안내(NaviHelper)는 이 UC 범위 밖이다

### 실행 환경·제약

- 주행 중 상호작용: 음성 안내 한 번만 한다. 응답이나 화면 조작을 요구하지 않는다(GAM-N01)
- 차량 신호: 트립 시간(Odometer)은 문서 확인 수준이다. 트립 시간이 언제 초기화되고 정차 시간을 포함하는지는 확인 필요 — GAM-Q25
- 주차 판단 후보: AAOS `GEAR_SELECTION`(P단), `PARKING_BRAKE_ON`([dev-environment.md](../../docs/contest/dev-environment.md) 4.3절). 어떤 조합을 쓸지는 GAM-Q1, 공통 Q8
- 관측과 해석: 주차 시간을 기록할 뿐 "휴식했다"고 단정하지 않는다. 신호 대기 같은 짧은 정차는 주차가 아니므로 휴식 시간에 넣지 않는다
- 보상 원칙: 돌발 퀘스트를 받으려고 오래 운전하게 만들면 안 된다. 하루 보상 횟수 상한 등은 GAM-Q26, GAM-N03
- 기준 시간과 휴식 인정 시간은 공개 근거가 필요하다. 근거 없이 수치를 정하지 않는다 — GAM-Q26
- 차량이 확인하는 관리 항목: Safety의 `getEngineOilLevelState`, `getBrakeFluidLevelState`, `getTransmissionOilLevelState`, `hasLowWasherFluidWarning`과 각 콜백은 `CAR_SAFETY`(normal)로 읽는다(문서 확인, [dev-environment.md](../../docs/contest/dev-environment.md) 4.2.1절). 에뮬레이터에서 값을 바꿀 수 있는지는 확인 필요 — GAM-Q40
- 관측과 해석: 레벨이 정상으로 돌아온 것만 본다. "보충했다", "정비했다"고 단정하지 않는다. 엔진오일 레벨은 양이지 교체 시기가 아니므로 정비 시기 퀘스트(A4~A6)와 따로 둔다
- 엔진오일 교체, 에어필터, 타이어 위치 교환을 알려 주는 차량 신호는 없다(GAM-Q4). 이 항목은 기록으로 완료한다(A6)

### 실행 환경·제약

- 주행·정차: 지도 조작은 주차 중에만 한다. 발자국 관측은 주행 중에 자동으로 하고, 주행 중에는 화면이나 음성으로 알리지 않는다
- 차량 신호: FusedLocation `isSupported()`, `registerFusedLocationCallback()`, `getLastKnownLocation()`, `addProximityAlert()`는 문서 확인 수준이다([dev-environment.md](../../docs/contest/dev-environment.md) 4.5절). 에뮬레이터 동작은 미검증이다
- 위치 권한: `FUSED_LOCATION`은 dangerous 권한이라 실행 중 동의가 필요하다. 동의 창은 주차 중에만 띄운다(A3). 거부해도 발자국만 빠진다(E1)
- 권역 판정: 중심점과 반경으로 볼지 행정 경계 데이터를 쓸지 정하지 않았다 — GAM-Q35

- 보상 원칙: 발자국은 재화를 주거나 도시 가격을 바꾸지 않는다(D-004). 먼 곳을 운전하게 만드는 동기가 되면 안 된다(GAM-N03)
- 저장과 외부 전송: 도시 ID와 첫 관측 날짜만 로컬에 저장한다. 차 밖으로 보내지 않는다(GAM-N09)

| E6 | B1에서 운전자가 동의하지 않음 | 연동하지 않고 아무것도 보내지 않는다. 차량 화면의 게임은 그대로다 | 취소 종료 |

### 실행 환경·제약

- 공모전 범위: 심사 대상은 Pleos Connect 앱이고 2차 PT도 에뮬레이터 시연이다([dev-environment.md](../../docs/contest/dev-environment.md) 1절). 폰 앱은 별도 클라이언트이며 확대 계획(P2)으로 둔다. 1차 목업에는 폰 화면 한 장면만 넣는다 — D-004
- 연동 수단: [SDK 문서] 5종에는 차량과 폰을 잇는 API가 없다(같은 문서 4절). 자체 서버를 쓴다고 가정했고 확인이 필요하다 — GAM-Q37. 외부 네트워크는 쓸 수 있다(같은 문서 1절)
- 주행·정차: 연동과 해제는 차량 화면에서 주차 중에만 한다. 차가 주행 중이면 폰 조작도 막는다(GAM-047). 주행 판단은 확인 필요 — 공통 Q8
- 관측과 해석: 차의 주행 여부만 본다. 폰 사용자가 운전자인지 동승자인지는 판단하지 않는다
- 외부 전송: 동의한 항목만 보낸다. 속도, 위치, 운전 관측값, 정비 기록은 보내지 않는다(GAM-N09)
- 개인정보: 실명, 연락처, 계정 ID를 요구하지 않는다
- 네트워크가 없으면 차량 화면의 게임은 단독으로 동작한다
