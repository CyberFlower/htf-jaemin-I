# GOAL: 내 차로 짓는 도시 (`GAM`)

> 상태: **Draft**. [draft/proposal-game.png](../../draft/proposal-game.png)(v0.1)에서 뽑았고 팀 합의 전입니다.
> 케어 요소는 [draft/proposal-care.html](../../draft/proposal-care.html)(CarCare Mate)에서 가져왔습니다. 이 기획안은 별도 프로젝트로 만들지 않고 game의 요소로 넣기로 했습니다([DECISIONS D-001](DECISIONS.md)).
> 합의된 항목은 사람이 옆에 `Confirmed (YYYY-MM-DD)`를 적고 [DECISIONS.md](DECISIONS.md)에 기록합니다.

## 한 줄 정의

운행과 소모 기록으로 보상을 얻어 원하는 모습으로 도시를 키우고, 도시를 보러 오는 길에 차량 관리 시기도 알아차린다.

## 기획 의도

- 평소 운전에 "오늘 내 도시는 어떻게 바뀔까?"라는 기대를 더합니다.
- 엔진오일, 에어필터, 타이어 위치 교환 같은 정기 관리는 잊기 쉽습니다. 도시를 보러 오는 과정에서 자연스럽게 알아차리게 합니다.
- (care) 획일적인 교체 주기(예: 1만 km)는 단거리 위주나 정체가 많은 운전 습관을 반영하지 못합니다. 두꺼운 매뉴얼은 초보 운전자가 찾아보기 어렵습니다.
- (care) 기존 서비스(정비 기록 앱, OBD-II 동글, 모바일 앱)는 폰 중심이고, 수동 입력이나 고정 주행거리 기준에 머뭅니다. 차량 자체 화면과 차량 데이터를 쓰면 이 한계를 넘을 수 있습니다. 창의성 근거의 출발점이며, 비교 대상은 조사해서 보강해야 합니다.

## 타깃 (가설)

- 아반떼, 그랜저, 투싼으로 출퇴근, 장보기, 주말 외출을 하고 도시 꾸미기를 가볍게 즐기는 차주
- (care) 차량 관리가 낯선 초보 운전자, 차를 오래 타고 싶은 장기 보유 운전자
- 두 타깃이 겹치는지, 아니면 주 타깃을 하나로 정할지 결정해야 합니다 → [GAM-Q19](OPEN_QUESTIONS.md)
- 이 차종에 Pleos Connect가 탑재되는지, 언제 탑재되는지 확인해야 합니다 → [GAM-Q8](OPEN_QUESTIONS.md)

## Goals

| ID | 목표 | 심사 |
|---|---|---|
| GAM-G1 | 주차 직후 차량 화면에서, 방금 이 차로 달린 결과(거리, 연료)가 도시 성장 보상으로 바로 보인다 | `[차량특화]` `[기술]` |
| GAM-G2 | 정기 관리를 퀘스트로 만들어, 거리와 기간 중 먼저 오는 기준으로 다음 정비 시기를 알아차리게 한다. 주기는 운전 습관(단거리 비율 등)으로 조정하고, 조정한 근거를 보여준다 (care) | `[차량특화]` `[창의]` `[사업]` |
| GAM-G3 | 실제 차량 경고를 도시의 이상 현상으로 표현하되, 실제 경고와 안내를 함께 보여 안전 정보를 가리지 않는다 | `[창의]` `[차량특화]` |
| GAM-G4 | 퀘스트를 확장할 수 있는 틀로 만들어 정비 알림, 동행 여정(grandma) 등 여러 출처의 목표를 담는다 | `[창의]` `[사업]` |
| GAM-G5 | "일상 운행 → 보상 → 꾸미기 → 다음 운행" 반복 루프와 확장(건축 테마, 시즌 팩) 가설을 지표로 검증할 수 있게 한다 | `[사업]` |
| GAM-G6 | (care) 주행 중에도 시선을 빼앗지 않도록, 차량 사용법과 관리 상태를 음성으로 묻고 답을 듣게 한다 | `[차량특화]` `[기술]` |

## Non-goals

- 주행 중 게임 플레이나 화면 조작
- 실제 경고를 게임 연출로 대체하거나 늦추기
- 과속, 급가속 같은 위험 운전에 유리한 보상
- 실결제와 인앱 구매 구현 (사업 모델은 설명까지만)
- 정비 이력 자동 수집 (차량 API를 확인하지 못했으므로 수동 기록부터)
- 소모품 상태의 진단 확정. 운전 습관 기반 추정은 "점검 권장"까지만 하고, "열화도 8,000km 수준" 같은 단정은 하지 않습니다 (care)
- 문서에서 확인되지 않은 차량 제어 API를 전제로 한 기능 (care의 음성 차량 제어는 확인 뒤 판단)

## 핵심 루프 (draft §01~03)

| 단계 | 내용 | 차량 데이터 |
|---|---|---|
| 1. 운행 | 이동 거리 → 건축 자재 (예: 11km → 11개). 연료 사용 → 보급 토큰 (예: 약 0.8L → 2개) | Odometer, Fuel |
| 2. 주차 후 | 이번 운행 결과를 확인합니다. 바로 쓰거나 다음 운행까지 모아 둡니다 | 주차 판단 (Q8) |
| 3. 건설 | 시설에 자재와 토큰을 씁니다 (예: 시장 = 자재 8 + 토큰 1, 공원 = 자재 6 + 토큰 2). 배치 조합 효과: 정류장 옆 시장 → 야시장, 공원 옆 무대 → 야외 공연 | — |
| 4. 관리 퀘스트 | 엔진오일 교체까지 1,000km 또는 18일. 마지막 교체 기록에 차종별 주기를 적용하고, 거리와 기간 중 먼저 오는 기준을 보여줍니다. 교체 기록 → 퀘스트 완료 → 다음 주기 | Odometer, CarInfo |
| 5. 이상 현상 | 공기압 경고 → 도로가 일렁입니다. 과열 경고 → 광장에 붉은 열기가 피어오릅니다. 실제 경고와 안내를 함께 보여주고, 경고가 풀리면 효과도 끝납니다 | Safety, Tire |

예시 수치는 draft의 설명용 값입니다. 보상 비율은 요구사항에서 정합니다(GAM-001, GAM-002).

## 퀘스트 구조 (GAM-G4)

퀘스트 출처를 나눠 두면 새 퀘스트 종류를 같은 틀로 더할 수 있습니다.

| 출처 | 예시 | 완료 조건 | 상태 |
|---|---|---|---|
| 정기 관리 | 엔진오일, 에어필터, 타이어 위치 교환 | 사용자의 교체 기록 | 후보 (GAM-006~008) |
| 차량 경고 | 공기압 경고 해소 | 경고 신호 해제 | 후보 (GAM-009와 연계) |
| 동행 여정 (grandma) | "할머니 모시고 저장한 카페 다녀오기" | 여정 완료 확인 | 후보 (GAM-012, Q1) |
| 운전 습관 케어 (care) | 단거리 위주 운전이 많을 때 엔진오일 점검을 앞당기는 퀘스트, 배터리 관리 퀘스트 | 점검이나 교체 기록, 배터리 상태 회복 | 후보 (GAM-013, GAM-014) |

|---|---|---|---|
| 동적 교체 주기 산출 (단거리, 공회전, 급제동) | 정비 퀘스트의 주기를 운전 습관으로 조정 | GAM-013 | 단거리 비율은 Odometer 트립 거리·시간으로 가능(문서 확인). 공회전과 급제동은 속도·시동 신호가 필요(확인 필요, Q8, GAM-Q17) |

## 성공 기준 (데모, 초안)

- [ ] Virtual Console에서 주행거리와 연료 값을 바꾸면, 주차 후 화면의 보상이 그에 맞게 바뀐다
- [ ] 정비 퀘스트: 교체 기록 입력 → 남은 거리와 기간 표시 → 기준에 도달하면 퀘스트 → 완료 후 다음 주기
- [ ] 경고 신호를 켜고 끄면 도시 효과와 실제 경고 안내가 함께 나타나고 사라진다
- [ ] 주행 중에는 게임 조작이 막히고 안내만 남는다

Virtual Console로 이 신호들을 바꿀 수 있는지는 확인해야 합니다([GAM-Q2](OPEN_QUESTIONS.md)).

## 원칙

- **안전 정보가 먼저입니다.** 경고는 원래 의미 그대로, 게임 효과보다 먼저 또는 함께 보여줍니다.
- **주행 중에는 조작하지 않습니다.** 상호작용은 주차 후에만 합니다.
- **보상은 실제 차량 데이터에 근거합니다.** 사용자가 입력한 값(정비 기록)은 차량 데이터와 구분해 표시합니다.
- **안전·친환경과 부딪히지 않는 보상을 설계합니다.** 연료 사용을 보상하는 방식은 다시 검토합니다([GAM-Q6](OPEN_QUESTIONS.md)). care의 운전 습관 분석이 효율·안전 운전 보상의 근거가 될 수 있습니다.
- **추정은 추정이라고 말합니다.** 운전 습관 기반 정비 시점은 근거와 함께 "점검 권장"으로 보여주고, 진단처럼 단정하지 않습니다.

## 사업성 메모 (양식 6번 대비, 미정)

- 반복 사용 동인 (draft §05): 일상 운행에서 자재와 토큰이 쌓이고, 다음 운행 뒤 기존 도시를 이어서 꾸밉니다
- 확장 가설: 건축 테마, 시즌 팩
- (care) 사용자 가치: 차량 수명 연장과 유지비 절감. 효과를 수치로 말하려면 근거가 필요합니다
- 측정 지표 후보 (팀 제안): 주차 후 앱 열람률, 주간 건설 횟수, 정비 퀘스트 완료율, 경고 확인 후 조치율
- 타깃 규모, 예상 MAU, Retention: **근거와 함께 작성 필요** → [GAM-Q8](OPEN_QUESTIONS.md)

## 다른 프로젝트와의 관계

grandma(`GRD`)의 동행 여정을 퀘스트 출처로 받는 안이 있습니다. 두 작품을 따로 낼지, 하나로 합칠지는 [open-questions.md](../../docs/open-questions.md) Q1에서 정합니다.
