# UI에서 도출한 UC 보완안

Draft / 2026-11-13. 실험 목업에서 도출한 Draft 제안입니다. ID 015~017은 기존 UC-014 다음의 제안 번호로, 실제 반영 전에 중복 여부를 확인해야 합니다. 기존 Decisions 형식과 사람의 확정 절차를 유지합니다.

## GRD-UC-015 목적지 주변에서 나와 동행자에게 맞는 장소 고르기

- 목표: GRD-G1·G2에 기여하는 제안. 장소 추천 전문성의 목표·우선순위는 추가 합의 필요.
- 주 행위자: 정차 중 여정을 준비하는 사용자.
- 트리거: 앱에서 목적지를 선택하고 주변에 들를 곳을 탐색한다.
- 입력 맥락: 목적지, 명시한 취향, 이번 동행 예정, 동행자의 확인된 선호, 날씨, 활용 허용한 과거 방문.
- 증강: 장소 속성·현재 조건을 연결해 후보를 비교하고 ‘왜 나에게 맞는지’를 설명한다.
- 성공 후 조건: 사용자가 근거를 이해하고 후보를 여정에 담는다. 예약·내비 적용·방문 완료는 별개다.
- 출처: 사용자 요청 1·2 및 이 HTML 목업의 선택 흐름. 새 기능 제안이며 기존 FR로 완전히 충족되지 않는다.
- 관련 결정: 없음. 기존 DECISIONS.md에 합의한 것처럼 기록하지 않는다.

| 흐름 | 사용자 행동 | 시스템 응답 |
|---|---|---|
| B1 | 목적지와 동행을 선택한다 | 목적지 주변 후보를 제한하고 확인된 맥락으로 정렬한다 |
| B2 | 음식점·카페·방문지를 필터링한다 | 해당 후보와 추천 근거, 방문 여부를 함께 보여준다 |
| B3 | 추천 이유를 확인한다 | 어떤 선호·현재 조건·방문 기억이 사용됐는지 설명한다 |
| B4 | 장소를 여정에 담는다 | 후보 목록에 추가하되 방문 스탬프는 바꾸지 않는다 |
| A1 | 새로운 곳 우선 선택 | 과거 방문 사실을 보존하면서 순위를 조정한다 |
| A2 | 비 오는 날로 변경 | 실내·야외 조건을 고려하고 이유를 갱신한다 |
| E1 | 동행 미정 또는 취향 없음 | 개인화를 확정하지 않고 확인된 조건으로만 주변 후보를 보여준다 |
| E2 | 속성이 확인되지 않음 | 적합성을 보장하지 않고 미확인 표시, 해당 속성의 가점 제외 |
| E3 | 주행 중 입력 요청 | 화면 조작을 막고 정차 후 재개 |

연결: UC-011(정보 전달)의 목적지 주변 탐색 구체화, UC-012(동행 의도), UC-014(근거 수정). 기존 GRD-003·006은 일부 맥락 공급 근거일 뿐, 추천·근거 경로·정렬·미확인 처리는 별도 FR이 필요하다.

## GRD-UC-016 방문한 장소와 새로운 장소를 탐험 기록으로 구분하기

- 목표: GRD-G4에 기여하는 제안.
- 주 행위자: 방문 경험을 확인하고 다시 찾는 사용자.
- 트리거: 장소를 탐색하거나 다녀온 후 기록을 남긴다.
- 사전 조건: 실제 방문 여부·시점·동행을 사용자가 확인할 수 있다.
- 성공 후 조건: 장소 단위 방문 상태와 방문별 경험이 일치하고, 과거 경험을 다시 볼 수 있다.
- 출처: 사용자의 ‘퀘스트를 깬 듯한 시각화’ 요청, UC-008·012·014 보강.
- 관련 결정: 없음. 과거 기록의 출처·편집 권한을 유지한다.

| 흐름 | 사용자 행동 | 시스템 응답 |
|---|---|---|
| B1 | 추천 카드·지도를 살펴본다 | 방문한 장소에 확인 스탬프, 미방문 장소에 새 발견 표시 |
| B2 | 실제 다녀온 장소의 기록을 남긴다 | 날짜·실제 동행·메모를 확인받는다. 동행 예정값을 자동 확정하지 않는다 |
| B3 | 방문을 확인한다 | 경험 기록을 추가하고 해당 장소의 스탬프를 채운다 |
| A1 | 같은 장소를 재방문한다 | 경험은 추가하지만 고유 방문 장소 수는 중복 집계하지 않는다 |
| A2 | 기억을 추천에서 제외한다 | 기록·스탬프는 유지하며 개인화 근거에서 제외한다 |
| E1 | 계획에만 담거나 위치만 근접한다 | 스탬프를 채우지 않는다 |
| E2 | 잘못된 기록을 수정·삭제한다 | 확인 후 해당 경험과 장소의 방문 상태를 재계산한다 |

연결: GRD-010(기록), GRD-N02(관측/해석 구분), UC-008·014. 스탬프 집계·재방문·수정 전파는 새 FR 필요. 위치 자동 판정이나 방문 보상은 본 목업 범위가 아니다.

## GRD-UC-017 추천의 장소 지식과 출처 확인하기

- 목표: GRD-G3에 기여하는 제안.
- 주 행위자: 추천의 적합성을 판단하는 사용자. 별도 운영 화면의 행위자는 지식 편집·검수 담당자.
- 트리거: 추천 이유에서 더 자세한 근거를 확인한다.
- 성공 후 조건: 장소 사실과 개인 경험, 확인된 내용과 미확인 내용을 구분해 판단한다.
- 출처: 사용자의 knowledge-base·graph 요청. 그래프 자체는 UI 메커니즘이며 사용자의 목표는 근거 판단이다.
- 관련 결정: 없음. 실제 수집·검수·저장 방식은 미정.

| 흐름 | 사용자 행동 | 시스템 응답 |
|---|---|---|
| B1 | 장소의 추천 이유를 연다 | 선택된 근거를 요약한다 |
| B2 | 연결된 지식을 탐색한다 | 장소→속성, 장소→방문 경험, 출처의 관계를 표시한다 |
| B3 | 근거 노드를 선택한다 | 출처·확인 시점·검증 수준·개인 기록의 활용 여부를 보여준다 |
| A1 | 기억 오류를 발견한다 | UC-014의 수정 흐름으로 연결한다 |
| E1 | 속성이 미확인·만료·상충한다 | 확인 필요 표시. 목업은 미확인 가점 제외까지만 구현하며 만료·충돌 정책은 후속 정의 |

일반 사용자의 핵심 화면에서는 간단한 이유·출처를 우선한다. 전체 그래프와 JSON 내보내기는 목업의 지식 검토 화면이다. 실제 편집·검수 담당자의 사실 등록/승인 UC는 후속 범위로 둔다.

## 기존 UC의 보완 지점

- UC-006·012: 동행 예정과 실제 방문 동행을 분리한다. 관계명으로 취향·보행 능력을 추정하지 않는다.
- UC-008: 장소별 확인된 방문을 저장한다. 여러 방문과 실제 동행의 연결을 유지한다.
- UC-011: 후보 검색 → 조건 반영 → 이유 설명 → 사용자 선택을 분리한다. 미확인 속성으로 적합성을 보장하지 않는다.
- UC-014: 활용 제외와 삭제를 다르게 처리하며, 두 동작이 추천과 방문 시각화에 미치는 영향을 안내한다.

## 14.6인치 차량 화면에서 추가로 드러난 요구

아래는 기존 UC와 Decisions를 수정하지 않는 Draft 보완안이다.

| 대상 | UC 보완 | FR 후보 / 관찰 가능한 수용 기준 |
|---|---|---|
| UC-015 추천 탐색 | 정차 중 한 화면에서 두 후보를 비교하고 다음 후보로 이동 | 페이지당 최대 두 곳. 끝에서는 다음 비활성화. 목적지·분류·취향 변경 시 첫 페이지로 복귀 |
| UC-012 동행 확인 | 이전 동행 기억을 제시하되 현재 동행 의도를 직접 확인 | 동행 예정 변경은 추천에 반영하되 실제 방문 기록의 동행자는 별도로 입력 |

| UC-017 근거 판단 | 요약 이유에서 자세한 장소 근거로 단계적으로 이동 | 카드 한 줄 이유 → 상세 → 사용자용 이유와 출처. 전체 그래프는 제작 검토 도구에 둠. 미확인 속성은 가점에서 제외 |

이번 화면은 정차 중 탐색을 중심으로 한다. 주행 중 음성 안내나 동승자 전용 조작은 별도 UC와 플랫폼 검토가 필요하며 구현 범위에 포함되지 않는다. 지식 그래프 전체 탐색을 실제 차량 제품에 노출할지, 별도 운영 화면으로 둘지는 미확정이다.


## 2026-11-14 · 정보량과 터치 흐름 보완

사용자 피드백에 따라 ‘한 화면에서 많은 정보를 비교’에서 ‘장소 선택 → 상세 확인 → 여정 담기’로 흐름을 바꾼다. 앞선 고정 지도 병렬 배치는 이 개정으로 대체한다.

- UC-015 B2 보완: 첫 화면은 최대 두 후보와 후보별 한 줄 이유만 제공한다. 분류·동행·목적지 변경은 여정 설정에서 수행하고 추천으로 돌아온다.
- UC-015 B3~B4 보완: 카드 전체를 눌러 상세를 열고 담기를 선택한다. 같은 카드 안에 서로 다른 작은 터치 동작을 겹치지 않는다.
- UC-016 B1 보완: 추천 카드에는 방문 여부만 표시하고, 지도와 패스포트는 별도 화면에서 탐색한다.
- UC-017 B1~B2 보완: 사용자 설명은 취향·동행·과거 방문의 구체적 이유를 제시한다. 그래프 탐색은 제작 검토용으로 분리한다.
- 터치 FR 후보: 주요 조작 영역의 논리 높이 64 이상 및 간격 16 이상. 정차 중 실제 디스플레이에서 오터치·가독성·과업 완료를 확인한 뒤 확정한다.
- 평가 과업: 추천 두 곳 중 한 곳 상세 확인·담기, 동행 변경 후 추천 복귀, 방문 여부 확인, 기억 수정. 기존 화면과 완료 시간·오터치·되돌아가기 횟수를 비교한다. 아직 사용자 평가는 시행하지 않았다.


## 2026-11-14 · 키보드 없는 방문 기록

UC-016 B2~B3를 다음 선택 흐름으로 보완한다. 기존 Decisions를 변경하지 않는 Draft다.

1. 장소 상세에서 기록을 시작한다. 발자국 화면에서 시작하면 장소 버튼을 먼저 고른다.
2. 오늘·어제·다른 날짜 중 방문 날짜를 선택한다. 다른 날짜는 연·월·일 증감 버튼으로 조정한다.
3. 실제 동행자를 직접 선택한다. 동행 예정값을 자동 확정하지 않는다.
4. 짧은 문구를 고르거나 한마디를 생략한다. 음성 경로에서는 인식 결과를 읽고 채택·재시도·취소한다.
5. 장소·날짜·동행·한마디를 확인한 뒤 저장한다. 그 전에는 스탬프를 바꾸지 않는다.

FR 후보: 방문 기록은 텍스트 입력 없이 완료할 수 있어야 한다. 음성 인식 실패·미지원·권한 거부 시 선택 입력으로 복귀해야 하며, 음성 결과는 사용자 확인 없이 저장하지 않는다. 수정도 같은 흐름을 사용하고, 닫으면 미저장 변경을 폐기한다. 한마디를 생략해도 방문 기록을 남길 수 있다.

현재 구현: 큰 버튼 선택, 단계별 질문, 최종 저장 확인, 음성 예시 채택/취소/실패 UI. 음성은 마이크를 쓰지 않는 시연이며 실제 인식·권한·네트워크 실패는 구현하지 않았다. 실제 음성 엔진과 차량 연동, 다양한 동행자 선택은 후속 범위다. 주행 중 음성 기록까지 허용한다는 결정은 하지 않았으며 기존 정차 전용 정책을 유지한다.
