# 차량 디스플레이 설계 기준

다녀왔습니다 HTML 목업의 화면 규격, 화면 구성, 시각 규칙, 검증 범위입니다.

## 1. 규격

- 기준: 14.6인치, 16:9 가로, 1920×1080. 논리 화면은 1280×720이며 1.5배에서 기준 픽셀 크기가 됩니다.
- 활성 화면의 물리 크기는 약 323×182mm, 약 151ppi입니다. 브라우저 창에 맞춘 축소 화면은 실제 14.6인치 크기를 보장하지 않습니다.
- 차량 화면 구조: 머리 72, 본문 584, 하단 시스템 64. 하단 공조 표시는 표시 예시이며 이 앱이 차량 기능을 제어한다는 뜻이 아닙니다.
- 이 규격은 설계 기준이며 에뮬레이터 실측값이 아닙니다(공통 Q4).

## 2. 화면 언어: 실로 잇는 기억

| 영역 | 크기(논리) | 내용 |
|---|---|---|
| 머리 | 1280×72 | 명조 브랜드, 글자 메뉴(홈·둘러보기·발자국·지도·내 AI·담은 곳, 높이 48), 날짜, 차량 상태, 시각 |
| 홈 실 | 1280×300 | 지난 사진(최대 3), 오늘 여정의 정류장, 운전자·동행자 빛, 내 AI 별빛, 약속 꼬리표, 매듭 |
| 홈 질문 | 왼쪽 64부터, 높이 284 | 관측 한 줄, 질문(명조 46), 설명, 근거, 대답 버튼 최대 2(높이 68) |
| 홈 바로가기 | 오른쪽 아래 | 기억 남기기·약속·지난 발자국(높이 48) |
| 주행(S09) | 본문과 메뉴 영역 전체(1280×584)를 덮고 머리까지 어둡게 | 빛나는 실, 두 빛, "○○까지", 남은 시간(명조 118), 음성 안내 한 줄. 버튼 없음 |

- 홈의 지금 카드 순서: 주행(S09) > 도어 관측 동행 후보 > 오늘 계획 > 귀가 후 다녀옴 확인 > 저장한 약속·기억 남기기. 첫 방문 기록 뒤에는 재방문 카드입니다.
- 첫 방문 화면(S02·S03·S04·S06·S07·S08)은 본문 584 안에서 머리 64 · 내용 · 하단 버튼 64 구조를 씁니다.
- 배경은 시각에 따라 아침(11시 전)·낮(15시 전)·늦은 오후(18시 전)·저녁입니다.
- 사람은 역할 그림입니다. 할머니는 은발 쪽머리·안경 얼굴, 어머니는 갈색 머리 얼굴, 사진 속에서는 뒷모습입니다.
- 동행 표시: 도어 관측은 동행자 자리에 흐린 점선 원만 띄웁니다. 운전자가 [네, 함께 가요]를 누른 뒤에만 빛을 채우고, 아니요면 빛을 그리지 않습니다.
- 버튼은 알약 모양입니다. 테두리 있는 웹 카드 대신 반투명 종이 면과 그림자로 묶습니다.

## 3. 음성 우선 화면과 내 AI

| 화면 | 구성 |
|---|---|
| 이번 여정 | 위쪽 작은 실(높이 130), 큰 마이크(112)와 질문(명조 40), 들은 문장(손글씨)과 고칠 수 있는 칩(높이 56), 지난 동행 질문, "내 AI 연결하기" 칩, 추천 보기(68), 접힌 "직접 고르기"(52) |
| 여정 계획 | "언제 갈지 말로 정하기"로 날짜·시각을 채우고 아래 칩으로 고칩니다 |
| 내 AI 연결 | 위쪽 작은 실(운전자 빛 + 내 AI 별빛), 공급자 버튼 3개(높이 66), 보내는 것/보내지 않는 것, 오른쪽 QR 카드(연결 시연 버튼 60) 또는 연결됨 카드(연결 끊기) |
| 둘러보기 + 내 AI | 살펴보는 중: 단계 목록과 "보낸 조건" 카드. 결과: 카드 두 장에 이유(손글씨, 파란 면), 출처 칩, 미확인 칩. 머리 오른쪽 "말로 다시 고르기"(56) |
| 이어 고르기 | 대화상자: 들은 말(손글씨)과 AI 답, 동행자 얼굴과 "기억에 남길까요?", [이번만 쓰기][남기기] |
| 방문 기록 시트 | 폭 1000, 제목은 방문 질문, 관측 한 줄, 장소·날짜·함께한 사람 줄(높이 54, 고치기 46), 한마디(마이크 76 + 추천 문구 52), 아래 [이대로 남기기] 하나 |

- 내 AI는 정차·주차 중에만 단계를 시작합니다. 주행 중 화면에는 별빛과 정리 결과 한 줄만 보입니다.
- 화면 문구는 "대한민국 명소발굴 추천지"로 씁니다.

## 4. 입력과 문구

- 주요 버튼·입력은 논리 높이 64 이상, 버튼 사이 간격은 16~24를 기준으로 합니다. 64 논리 단위는 기준 해상도에서 96픽셀, 약 16mm입니다. 지도 핀·스탬프도 64입니다.
- 입력은 음성이 기본입니다. 텍스트 박스와 네이티브 날짜 입력은 쓰지 않습니다. 음성 시연에는 실제 녹음이 없다는 표시가 있고, 인식 결과 확인·재시도·취소·실패 복귀를 구분합니다.
- 문구는 "조용한 곳을 좋아하셔서", "지난번 어머니와 다녀온 곳이에요"처럼 장소를 고르는 데 필요한 이유를 씁니다. 구조와 계산 방식의 설명은 화면 밖 제작 검토 도구(지식 모델 검토, JSON)에 둡니다.
- 주행·차량 상태 미확인 시연에서는 본문과 메뉴를 inert로 만들고 코드에서도 입력을 막습니다. 정차로 바꾸면 맥락과 여정 후보가 그대로 남습니다.
- 시연 도구는 차량 화면 밖 오른쪽(폭 272px)에 있고 차량 상태와 외부 응답만 바꿉니다. `embed=1`이면 숨깁니다. 이 도구는 사용자 화면 기준(64 터치 등)의 대상이 아닙니다.

## 5. 색과 글꼴

- 기본 토큰: 크림 배경 `#f7efe3`, 종이 `#fffaf2`, 글자 `#3b2a20`, 주색 테라코타 `#b4532a`(흰 글자 4.99:1), 보조 글자 `#76604f`(종이 위 5.68:1).
- 실 `#a8482a`, 동행자 빛 분홍 `#f2b3a0`, 주행 배경 `#1d1511`.
- 내 AI: 별빛 `#6f86d6`~`#a9b9f0`, 이유 면 `rgba(238,242,255,.75)`, 글자 `#3b4a86`.
- 대비: 기본 토큰은 WCAG 계산값입니다. 하늘빛 배경과 내 AI 색 위의 글자 대비는 아직 계산하지 않았습니다(확인 필요).
- 글꼴: 제목 Gowun Batang, 기억·약속·사진 설명 Nanum Pen Script, 안내·버튼 Noto Sans KR. 모두 Google Fonts(OFL)에서 받고, 오프라인이면 기본 글꼴로 대신합니다. 차량 앱에 넣을 수 있는지는 확인 필요입니다.

## 6. 차량 제조사 앱과 비교해 검증할 가설

차량 제어보다 사람의 기억과 목적지 주변 장소 지식의 연결에 집중합니다. 추천의 전문성은 그래프의 복잡도가 아니라 확인할 수 있는 장소 속성, 운전자가 확인한 동행 선호, 이전 경험을 이번 여정에 적용하는 품질에서 나옵니다. 설명을 읽고 후보를 고를 수 있는지, 잘못된 기억을 고친 뒤 추천이 바뀌는지로 평가합니다.

목업의 localStorage는 현재 브라우저에만 저장하므로 차량 간 이동을 구현한 것은 아닙니다.

## 7. 검증 범위

- jsdom 상호작용 테스트(`npm test`): 배율 계산, 두 장 페이지 이동, 필터 초기화, 추천 근거, 동행 예정과 실제 방문 분리, 기록 수정·제외·삭제, 입력 제한, 저장, 방문 기록 시트(동행 필수, 저장 전 미기록), 내 AI(미연결·실패 시 기본 추천, 동의 없는 취향 미저장, 주행 중 단계 없음).
- 화면 확인: Chromium(Playwright) 1920×1080에서 SC-01~08과 기억 남기기, 약속·계획·승인·출발 준비·동행 확인, 방문 기록 시트, 둘러보기·내 AI·이어 고르기, 발자국·지도·이번 여정을 찍어 겹침과 잘림을 확인했습니다.
- 남은 검증: 실제 차량 디스플레이의 시야 거리, 장착 각도, 밝기, 입력 지연, 터치 사용성, 플랫폼 가이드 적합성. jsdom 테스트는 시각 검증을 대신하지 않습니다.
