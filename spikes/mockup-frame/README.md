# 목업 틀

두 출품작의 목업을 차량 화면 비율로, 대표 시나리오의 장면 순서대로 보여 주는 화면입니다. 시연 영상을 녹화하고 화면 시안을 캡처할 때 씁니다. 앱 자체가 아니라 목업을 담는 틀입니다.

규칙은 [docs/process/submission-package.md](../../docs/process/submission-package.md)에 있습니다.

## 여는 방법

`index.html`을 브라우저(Chrome, Edge, Safari)에서 엽니다. 설치, 빌드, 서버, 외부 네트워크가 필요 없습니다.

틀에 보이는 글자는 앱 이름, 장면 번호, 장면 이름, 차량 상태뿐입니다. 버튼은 아이콘이고, 마우스를 올리면 이름이 나옵니다. 장면 설명은 `SCENARIO.md`에서 읽습니다.

| 조작 | 키 | 하는 일 |
|---|---|---|
| 이전 / 다음 | `←` / `→` | 장면을 넘깁니다. 아래의 번호를 눌러도 됩니다 |
| 장면 이름 | `C` | 화면 아래의 장면 이름과 차량 상태를 켜고 끕니다 |
| 쓰는 SDK | `S` | 장면 이름 옆에 그 장면에서 쓰는 Pleos SDK를 켜고 끕니다(기본은 꺼짐). 내용은 `SCENARIO.md` 2절 "SDK" 칸입니다. 영상에서 기술 활용성을 보여 줄 때 켭니다 |
| 녹화 모드 | `R` | 앱 이름, 버튼, 장면 번호를 숨깁니다. 차량 화면과 장면 이름만 남습니다 |
| 전체 화면 | `F` | 브라우저 전체 화면 |

- 목업(iframe) 안을 누른 뒤에는 키가 목업으로 갑니다. 틀의 바깥을 한 번 누르면 단축키가 다시 동작합니다.
- 주소 끝의 `#game/SC-03`처럼 앱과 장면을 지정해 열 수 있습니다. `#game/SC-03/rec/nocap`은 녹화 모드에 장면 이름도 끈 상태로, 차량 화면만 나옵니다.
- 테두리 안이 앱 화면입니다. 테두리 밖의 장면 번호와 이름은 시연 안내입니다.
- 점선 번호는 아직 화면을 연결하지 않은 장면입니다.

## 장면을 넣는 방법

장면의 원본은 `projects/<p>/SCENARIO.md` 2절 장면 표입니다. `data/*.js`는 생성된 파일이므로 손으로 고치지 않습니다.

1. 장면 표의 "틀" 칸에 목업 파일이나 캡처를 `[이름](상대 경로)`로 연결합니다. 경로는 `SCENARIO.md`가 있는 폴더 기준입니다.
   - HTML 목업: `[목업](../../spikes/<주제>/index.html?embed=1#home)`
   - 캡처 이미지: `[캡처](assets/scenes/SC-03.png)`
2. 저장소 루트에서 `node spikes/mockup-frame/build.mjs`를 실행합니다. Node.js만 있으면 됩니다.
3. `index.html`을 새로 고쳐 확인하고, 바뀐 `data/*.js`를 함께 커밋합니다.

"틀" 칸이 `TODO`인 장면은 장면 번호와 이름만 적힌 자리표시로 나옵니다. 그래서 화면이 없어도 장면 순서를 먼저 검토할 수 있습니다.

`build.mjs`는 앱별로 남은 빈칸(`SCENARIO.md`와 `PROPOSAL.md`의 `TODO`)도 함께 보여 줍니다. `--check`를 붙이면 쓰지 않고 검사만 합니다.

### 목업을 장면별 캡처로 넣기

목업이 장면 상태를 주소로 받지 못하면(예: 시뮬레이터 패널로 상태를 바꾸는 목업) 장면마다 캡처를 만들어 연결합니다. game은 `capture/game.cjs`가 [game 목업](../game-isometric/README.md)의 시뮬레이터 버튼과 전역 함수로 SC-01~SC-07 상태를 만들고 차량 화면(1920×1080)만 찍어 `projects/game/assets/scenes/`에 저장합니다. 목업 코드는 바꾸지 않습니다.

```bash
node spikes/mockup-frame/capture/game.cjs
```

- Playwright와 Chromium이 필요합니다(`require('playwright')`).
- 목업이나 장면 순서가 바뀌면 다시 실행하고, 바뀐 PNG를 함께 커밋합니다.
- 캡처의 숫자는 목업 가정값입니다. 원고 수치로 옮기지 않습니다.

## 파일

- `index.html`: 틀. 외부 의존성이 없는 단일 파일입니다.
- `build.mjs`: 장면 표 → `data/<p>.js` 생성, 빈칸 보고. 외부 의존성이 없습니다.
- `data/<p>.js`: 생성된 장면 데이터.
- `capture/game.cjs`: game 목업 장면 캡처 스크립트(Playwright).
- `capture/grandma.cjs`: grandma 장면 캡처 스크립트(Playwright). 화면 시안용 PNG를 `projects/grandma/assets/scenes/`에 만듭니다.

새 프로젝트를 더하면 `index.html`의 `<script src="data/...">` 줄을 하나 추가합니다. 빠뜨리면 `build.mjs`가 알려 줍니다.

## 검증과 한계

- 2026-11-14에 Chromium(Playwright)으로 두 앱의 장면 넘기기, 녹화 모드, 장면 이름 끄기, 자리표시 화면을 확인했습니다. HTML 목업(iframe)과 캡처 이미지 연결은 시험용 파일로 확인한 뒤 되돌렸습니다.
- 2026-11-14에 game 장면 7개를, 2026-11-15에 전국 지도 SC-08·새 도시 열기 SC-09를 캡처로 연결했습니다(`capture/game.cjs`). grandma는 2026-11-15부터 SC-01~08 모두 [HTML 목업](../grandma-journey-context/README.md)(`journey-demo.html?embed=1#SC-0N`)에 연결되어 있습니다. 같은 날 첫 방문 목업을 이 목업에 통합했습니다. 링크의 `?`와 `#`을 모두 보존하도록 `build.mjs`를 고쳤습니다.
- 화면 규격은 `SCENARIO.md` 1절의 "화면 규격" 줄을 읽습니다. 지금 값(1920×1080)은 에뮬레이터 실측값이 아닙니다([open-questions.md](../../docs/open-questions.md) Q4).
- 틀은 목업을 그대로 띄울 뿐입니다. 목업 안의 상태(어느 화면, 어느 차량 신호)는 목업이 주소(`#...`, `?...`)로 받도록 만들어야 장면마다 다르게 열 수 있습니다.
- 차량 신호, SDK, 에뮬레이터와 연결되지 않습니다. 실제 차량 화면의 크기, 밝기, 터치 사용성을 보장하지 않습니다.

## 실험 목적과 결론

- 목적: [ADR-0002](../../docs/decisions/0002-mockup-implementation.md)가 Proposed인 동안, 목업 구현 방식(웹 목업, 캡처 이미지)과 상관없이 두 앱의 목업을 같은 모양으로 보여 주고 장면 순서를 `SCENARIO.md`와 맞추는 방법을 확인합니다.
- 현재 결론: 장면 표 하나에서 틀의 장면 순서를 생성하는 방식이 동작합니다. 화면이 없는 장면도 자리표시로 순서를 검토할 수 있습니다.
- 미확인: 실제 목업을 연결한 상태의 녹화 품질, 에뮬레이터 화면 규격.
- 이 실험은 제품 구현 방식을 정하지 않습니다. ADR-0002가 정해지면 위치(`spikes/`)를 다시 정합니다.
