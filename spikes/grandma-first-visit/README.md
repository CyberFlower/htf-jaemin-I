# spike: grandma-first-visit (다녀왔습니다 첫 방문 여정 목업)

> 상태: 실험 코드. 제품 코드가 아닙니다([ADR-0002](../../docs/decisions/0002-mockup-implementation.md)는 Proposed 그대로입니다).
> 기준 문서: [SCENARIO.md](../../projects/grandma/SCENARIO.md) SC-01~07, [USE_CASES.md](../../projects/grandma/USE_CASES.md) "화면 흐름"과 "대표 시나리오를 화면으로 따라가기", [REQUIREMENTS.md](../../projects/grandma/REQUIREMENTS.md), [SDK.md](../../projects/grandma/SDK.md)
> 작성일: 2026-11-15

## 1. 목적

- 대표 시나리오 "이번 일요일, 할머니 모시고 저장해 둔 바다 카페에 다녀오기"의 첫 방문(SC-01~07)을 차량 화면에서 처음부터 끝까지 눌러 볼 수 있게 합니다.
- 장면마다 주소(`#SC-01`~`#SC-07`)로 바로 열 수 있게 해서 [목업 틀](../mockup-frame/README.md)과 시연 영상에 씁니다.
- 재방문 여정(SC-08)은 기존 [grandma-journey-context](../grandma-journey-context/README.md) 목업이 맡습니다. 이 목업은 그 코드를 고치지 않고, 색과 차량 화면 구조(위 줄 72, 본문 584, 차량 시스템 줄 64, 논리 1280×720)를 맞췄습니다.

## 2. 실행

`index.html`을 Chrome·Edge·Safari로 엽니다. 설치, 빌드, 서버, 외부 네트워크가 필요 없는 단일 파일입니다.

| 주소 | 하는 일 |
|---|---|
| `index.html` | 차량 화면과 오른쪽 시연 도구. 마지막 상태를 이 브라우저에 저장해 이어 갑니다 |
| `index.html#SC-03` | 해당 장면의 처음 상태로 엽니다 |
| `index.html?embed=1#SC-03` | 시연 도구와 테두리를 숨기고 차량 화면만 창에 맞춰 보여 줍니다(목업 틀용) |

## 3. 장면과 화면

화면 ID(`S##`)는 [USE_CASES.md](../../projects/grandma/USE_CASES.md) "화면 목록"을 따릅니다.

| 장면 | 처음 상태 | 눌러 보는 순서 | 화면 | 요구사항 |
|---|---|---|---|---|
| SC-01 기억 | 정차, 약속 없음 | 지금 카드 `🎙 기억 남기기` → 마이크 → `이대로 쓰기` → 바다 카페 → 할머니 → `약속 저장` | S01 → S02 → S03 | GRD-001, GRD-002 |
| SC-02 조율·확정 | 정차, 약속 저장됨 | `여정 만들기` → 이번 일요일·10:30 → `승인할 작업 확인` → 체크 → `계획 확정` | S03 → S04 → S06 | GRD-003, GRD-005 |
| SC-03 출발 | 일요일 10:02, 계획 확정 | 지금 카드 `준비 점검` → (연료 40%면) `경유 추가` 또는 `건너뛰기` → `1구간 경로 적용` | S01 → S07 | GRD-006, GRD-007 |
| SC-04 주행 (1구간) | 주행 | 조작 없음. 다음 목적지·남은 시간·음성 안내 한 줄 | S09 | GRD-N01 |
| SC-05 동행 | 할머니 댁 앞 정차, 도어 열림→닫힘 관측 | 지금 카드 `확인하기` → `네, 함께 가요` → `2구간 경로 적용` | S01 → S08 | GRD-008, GRD-007 |
| SC-06 주행 (2구간) | 주행 | 조작 없음. 약속의 맥락을 담은 안내 한 줄 | S09 | GRD-N01 |
| SC-07 다녀옴 | 귀가 후 주차 | 지금 카드 `기록하기` → 방문 확인 → 함께한 사람 → 한마디 → `확인하고 저장` → 약속 완료 | S01 → S10 | GRD-010, GRD-016 |

시연 도구(차량 화면 밖)로 바꾸는 것:

| 조작 | 대신하는 것 |
|---|---|
| `P 정차·주차` / `D 주행` | 주행/정차 판단(AAOS, 공통 Q8·Q11). 주행이면 주행 모드로 바뀌고 화면 입력을 받지 않습니다 |
| `도어 열림 → 닫힘` | Vehicle Door 관측(`CAR_DOORS`) |
| `연료 40%` / `연료 80%` | Vehicle Fuel / EvBattery(`CAR_ENERGY`). 40%면 경유 제안이 나옵니다 |
| 내비 응답 `성공` / `실패` | NaviHelper 경로 적용 요청의 결과 콜백. 실패하면 "계획은 그대로" 상태가 됩니다 |

`P`와 `D`를 번갈아 누르면 장면이 이어집니다: 출발 전(SC-03) → `D`(SC-04) → `P`(할머니 댁 도착) → `도어 열림 → 닫힘`(SC-05) → `D`(SC-06) → `P`(귀가, SC-07).

## 4. 지키는 원칙 (요구사항에서 옮김)

- 음성은 사용자가 마이크를 누를 때만 듣고, 인식 결과는 "이대로 쓰기"를 눌러야 씁니다(GRD-002).
- 장소 후보와 동행자는 사용자가 골라야 저장합니다. 정보가 없으면 "미확인"으로 둡니다(GRD-003).
- 계획을 확정해도 바로 실행하지 않고, 체크한 작업만 그 시점에 실행합니다. 지원 여부를 모르는 공조는 체크할 수 없습니다(GRD-005, GRD-009).
- 경로 적용은 내비게이션 응답을 받은 뒤에만 "적용됨"으로 바꿉니다. 실패하면 계획을 지우지 않습니다(GRD-007).
- 도어 열림·닫힘은 관측 근거로만 보여 주고, 탑승과 신원은 사용자가 확인합니다(GRD-008, GRD-N02).
- 정차 42분은 방문 후보일 뿐이고, 사용자가 확인해야 기록합니다. 저장 전에는 아무것도 기록하지 않습니다(GRD-010, GRD-016).
- 주행 중에는 화면 조작을 받지 않고 안내 한 줄만 보여 줍니다(GRD-N01).

## 5. 가정과 한계

- 장소, 거리, 시각, 날씨, 연료, 도어 관측, 내비 응답, 음성 인식은 모두 **시연용 값**입니다. Pleos SDK와 에뮬레이터에 연결하지 않았습니다.
- 가족 공유 페이지(GRD-004, GRD-Q1), 출발 소식 초안(GRD-012), 다녀온 곳(S11)과 사람·장소 관리(S12) 화면은 만들지 않았습니다. 공조는 "지원 여부 미확인"으로만 보여 줍니다(GRD-Q4).
- 사진 고르기는 방법이 정해지지 않아(GRD-Q12) 안내 문구만 둡니다.
- 1920×1080(16:9)은 기존 목업과 같은 설계 기준이고 에뮬레이터 실측값이 아닙니다(공통 Q4).
- 2026-11-15에 Chromium(Playwright)으로 SC-01~07 흐름 전체, 장면 주소로 열기, `embed=1` 표시를 확인했습니다. 페이지 오류는 없었습니다. 실제 차량 디스플레이의 터치·가독성은 확인하지 않았습니다.

## 6. 결론

- 첫 방문 SC-01~07을 빌드 없는 HTML 한 파일로 눌러 볼 수 있습니다. 목업 틀의 grandma 장면이 8/8 연결됩니다.
- 재방문(SC-08) 목업과 화면 구성이 다르므로, 두 목업을 하나로 합칠지는 GRD-Q26에서 정합니다.
- 이 실험은 구현 방식(ADR-0002)을 정하지 않습니다.
