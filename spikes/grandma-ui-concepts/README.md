# 다녀왔습니다 화면 콘셉트 (A+ 채택, 2026-11-15)

지금 [journey-context 목업](../grandma-journey-context/README.md)은 왼쪽 메뉴, 큰 카드, 아래 타일 세 개로 된 웹 대시보드 구조입니다. 차 안에서 쓰는 가족 앱다운 화면 방향을 찾기 위해 같은 네 장면을 세 방향으로 다시 그렸습니다.

- 대상 장면: 1 기억(SC-01), 5 동행 확인(SC-05), 4 주행(SC-04), 7 다녀옴(SC-07). A+는 6 바다 카페로(SC-06)와 다녀옴 확인 뒤 화면을 더했습니다.
- 문구, 시각, 사진은 예시입니다. 기능, 장면 순서, 차량 신호 규칙은 바꾸지 않습니다.

## 여는 방법

`concepts.html`을 브라우저에서 엽니다. 글꼴(Gowun Batang, Nanum Pen Script, Noto Sans KR)은 Google Fonts에서 받고, 오프라인이면 기본 글꼴로 보입니다.

- `concepts.html?solo#AA-2`처럼 열면 한 장면만 1920×1080으로 보입니다.
- 캡처: `node spikes/grandma-ui-concepts/capture.cjs <concepts.html 절대 경로> <출력 폴더>` (Playwright)
- `shots/gallery.png`: 세 방향 한눈에 보기, `shots/current-SC-05.png`: 지금 목업 비교용

## A+. 실로 잇는 기억 (A 발전안, 2026-11-15)

A의 선을 실로 바꾸고 감성 요소를 더했습니다.

| 요소 | 화면 | 의미 |
|---|---|---|
| 실 | 위쪽에 늘어진 빨랫줄. 지나온 구간은 꼬인 실, 아직 안 간 구간은 점선 | 기억과 약속이 이어져 있다 |
| 사진 | 다녀온 곳은 빨래집게로 건 폴라로이드, 손글씨 설명 | 지난 기억 |
| 꼬리표 | 아직 가지 않은 약속은 손글씨 꼬리표("저 카페 한번 가 보고 싶다") | 다음 약속 |
| 빈 사진틀 | 기억을 남기려는 자리에 "?" 사진틀 | 지금 채울 기억 |
| 두 개의 빛 | 운전자(호박색)와 할머니(분홍). 할머니 빛은 운전자가 "함께 출발해요"를 누르기 전에는 빈 원 | 함께 간다는 것 |
| 할머니 | 할머니 빛 안의 얼굴 그림(기다릴 때는 흐리게), 약속 꼬리표의 작은 얼굴 서명, 함께 다녀온 사진 속 나란히 앉은 뒷모습 | 이 여정의 주인공. 실제 사진이 아니라 가족 역할 그림 |
| 매듭 | 다녀옴을 확인하면 꼬리표가 사진으로 바뀌고 실에 매듭 | 약속을 지켰다 |
| 하늘빛 | 오후·아침·저녁 하늘. 주행 중에는 어두운 배경에 실이 전구 줄처럼 빛남 | 하루의 흐름 |

- 화면 위쪽은 늘 실, 아래쪽은 질문 한 문장과 큰 대답 둘(B의 장점)입니다.
- 다녀옴의 대표 장면은 C의 소인 대신 "꼬리표 → 사진 + 매듭"입니다.
- 문 열림은 할머니 자리의 빈 원을 띄우는 계기일 뿐이고, 빛을 채우는 것은 운전자의 대답입니다.

## 내 AI 연결 (A+ 확장안, 제안)

운전자가 쓰던 Claude, ChatGPT, Gemini 중 하나를 연결하는 기능의 화면 제안입니다(`concepts.html` "내 AI 연결" 절, `#AI-1`~`#AI-5`).

| 장면 | 화면 |
|---|---|
| AI-1 연결 | 쓰던 AI 고르기, 휴대폰 QR로 이어서 연결, 보내는 것과 보내지 않는 것 |
| AI-2 조사 | 별빛(내 AI)이 목적지 쪽으로 가며 관광 정보·100×100·내 기록을 살펴봄. 보낸 조건 표시 |
| AI-3 추천 | 두 곳, "Claude가 정리한 이유", 출처 칩, 미확인 칩 |
| AI-4 이어 묻기 | 한마디(음성 인식 텍스트)로 다시 고르고, 새 취향은 허락받아 할머니 기억에 저장 |
| AI-5 주행 | 출발 전에 정리한 결과만 음성 안내. 주행 중에는 AI에 묻지 않음 |

- 장소 이름(솔바람 찻집, 파도 서가)과 100×100 주제명은 가상 예시입니다.
- 연결은 사용자가 발급한 API 키를 휴대폰에서 등록하는 방식입니다([DECISIONS.md](../../projects/grandma/DECISIONS.md) D-001).

## 세 방향

| 방향 | 한 줄 | 장점 | 위험 |
|---|---|---|---|
| A. 한 줄의 여정 | 메뉴 대신 선 하나. 왼쪽 지난 기억, 가운데 지금, 오른쪽 다음 약속 | 앱 정의("기억을 다음 약속으로")가 그대로 화면. 주행 중엔 선이 경로 | 기억이 쌓이면 붐빔. 계획·승인 상세 화면을 따로 설계해야 함 |
| B. 말을 거는 차 | 차가 건네는 한 문장 + 큰 대답 두 개. 배경이 시간·날씨를 따름 | 음성 우선, 시선 부담 최소, 화면 문장 = 음성 안내 | 지난 기억·약속 탐색이 약함 → 아래 서랍으로 보완 |
| C. 가족 엽서 | 약속은 엽서, 기억은 폴라로이드, 다녀오면 "다녀왔습니다" 소인 | 감성·브랜드 가장 강함, 영상의 대표 장면 | 장식이 많으면 가독성 저하, 사진 없을 때 빈 상태 필요 |

## 제안

- 평소 화면과 주행 화면은 B로 만듭니다.
- 약속을 남기는 순간과 다녀온 순간에만 C의 엽서와 소인을 씁니다.
- 지난 기억을 둘러보는 "발자국" 화면은 A의 선으로 만듭니다.

## 지킨 것

- 주행 중 화면에는 버튼이 없습니다. 음성 안내 문장과 남은 시간만 있습니다.
- 차량 신호는 관측 사실로만 작게 씁니다("문이 열렸다 닫혔어요"). 탑승·방문은 운전자가 답합니다.
- 정차 중 버튼은 높이 116px 이상입니다. 아래 차량 시스템 영역은 가리지 않습니다.

## 실험 목적과 결론

- 목적: journey-context 목업의 시각 방향을 팀이 고를 수 있게 비교안을 만듭니다.
- 결론: 2026-11-15 A 방향을 바탕으로 A+를 만들었고, 같은 날 A+를 [journey-context 목업](../grandma-journey-context/README.md) 전체(SC-01~08)에 적용했습니다. 이 폴더는 디자인 결정의 근거(비교안)로 남깁니다. 팀 검토가 끝나면 지워도 됩니다.
- 미확인: 실제 차량 화면 밝기·거리에서의 가독성, 세리프·손글씨 글꼴의 라이선스와 앱 탑재 여부.
