“이번 일요일, 할머니 모시고 꽃 보러 갈까?”

사용자가 전달한 메시지와 저장한 약속으로 초안을 만듭니다. 날씨·장소 정보와 사용자가 선택한 일정을 참고하고, 가족은 공유 링크에서 시간과 후보를 선택합니다. 확정은 운전자가 승인합니다.

“오늘 여정을 시작할까요? 할머니께 보낼 출발 소식도 준비했어요.”

날씨와 차량 상태를 갱신하고 필요한 경유를 제안합니다. 목적지 설정만으로 메시지를 보내지 않습니다. 실제 출발을 확인한 뒤 승인된 공유 경로를 사용합니다. 주행 중 화면 조작을 요구하지 않습니다.

“할머니와 함께 출발하시나요? 저장한 공조 설정을 적용할까요?”

정차 중 도어·좌석 신호로 탑승 후보를 감지하되, 누구인지는 확인합니다. 이전에 승인한 동행 설정과 카페 경유 계획을 적용합니다. 좌석 신호가 제공되지 않으면 수동 확인으로 진행합니다.

실제 이동과 확인한 방문으로 기록 초안을 만듭니다. 사용자가 사진과 한마디를 더해 저장·공유하고 약속의 완료를 확인합니다. 다음에 함께하고 싶은 일이 있다면 새 여정 후보로 남깁니다.

경로·공조·전송 작업을 구분해 승인합니다. 주행 중 확인을 강요하지 않습니다.

05 · 회고필요한 기억만

도착 후 한 번의 선택적 회고. 초안을 수정하고 공유 범위를 직접 정합니다.

관측과 해석을 구분합니다. 정차는 방문 확정이 아니며, 좌석 점유는 신원 확인이 아닙니다. 지연을 사고로 단정하거나, 기록에 없는 대화·감정을 생성하지 않습니다.

05 / 기술 실현성

차량 SDK는 여정의 ‘관측’과 ‘실행’을 담당합니다.

다이어리·공유만으로는 차량 앱의 이유가 약합니다. 현재 차량 상태로 출발을 준비하고, 동행 경험을 경로와 차량 설정에 반영하는 것이 핵심입니다.

검증 상태: 아래 항목은 제공된 설명회 요약에 근거한 설계 후보입니다. 공식 SDK 문서에 접근하지 못해 개별 API·권한·데이터 갱신·에뮬레이터 지원 여부는 검증하지 못했습니다. 지원 확정 목록이 아닙니다.

표는 좌우로 스크롤할 수 있습니다.

영역사용 목적확인 사항 / 대체 동작

STT / TTS짧은 기억 입력과 안내검증 필요 언어·오프라인 지원 확인. 텍스트 입력 대안 제공, 상시 녹음 제외.
06 / 외부 앱 연계

가족에게는 익숙한 앱으로,
차량에는 승인된 계획으로.

연동 범위는 제공 API·인증·서비스 정책에 따라 결정합니다. 비공개 채팅·사진·연락처를 자동으로 읽는 기능을 전제하지 않습니다.

COMMUNICATION

메신저 + 가족 공유 웹

이미지·텍스트·링크를 지원되는 공유 방식으로 전달합니다. 가족은 웹페이지에서 시간·장소 후보에 응답합니다. 메시지 수신 의사와 공유 범위를 확인합니다.

PLANNING

캘린더 + 날씨·장소

한 종류의 캘린더부터 인증·권한을 검증합니다. 날씨와 영업·주차 정보는 출처·시점을 표시하고, 실행 전에 갱신합니다. 정보가 없으면 미확인으로 둡니다.

MEMORY

사진 선택 + 여정 카드

사용자가 선택한 사진만 기록에 추가합니다. 실제 경로·연락처·주거지 주소는 기본 공유에서 제외하고, 가족에게 보여줄 내용은 미리보기로 확인합니다.

차량에서 직접 SMS·메신저 전송이나 OS 공유가 가능하다고 가정하지 않습니다. 휴대전화·공유 웹을 통한 전달을 우선 검토하고, 자동 발송은 별도 서버·서비스 인증과 수신 동의를 검증한 후 확장합니다.

07 / 첫 구현 범위

기능을 늘리기보다, 한 번의 약속을 완주합니다.

대표 시나리오는 ‘할머니를 모시고 저장한 카페에 다녀오기’입니다. 명절 귀성·공항 배웅·가족 여행은 같은 구조를 확장할 후속 시나리오로 둡니다.

핵심 MVP

  1. 사람·장소·약속 등록: 위치와 관계를 연결하고 다음에 갈 장소 저장.
  2. 여정 초안·가족 공유: 날씨·장소 조회, 공유 웹에서 후보 선택. 일정은 수동 입력부터 지원.
  3. 차량 실행: 차량 상태 조회와 승인한 내비 목적지·경유지 연동.
  4. 동행·기록: 정차 중 동행자 확인, 실제 방문을 반영한 기록 수정·저장·선택 공유.

기술 검증 후 확장

  • 캘린더: 한 종류의 조회·등록 연동부터 추가.
  • 탑승 자동 감지: 도어·좌석·정차 신호 조합. 사람의 신원은 확인 유지.
  • 공조 개인화: HVAC 쓰기 권한과 상태 반영 검증 후 추가.
  • 출발 소식 자동 발송: 수신 동의·발송 경로·중복 방지 검증 후 추가.
1

가장 먼저: SDK 실현성 스파이크

에뮬레이터에서 위치·차량 상태 조회와 내비 경유 연동을 실제 확인. 도어·좌석·HVAC 지원표를 작성하고 MVP 범위를 확정합니다.

2

중간 목표: 기억에서 계획까지 연결

약속 저장 → 외부 정보 조회 → 가족 응답 → 운전자 승인까지 연결. 외부 API 실패 시에도 수동 계획을 유지합니다.

3

최종 데모: 기억이 실제 길을 바꾸는 장면

공유한 가족 선택이 경유지에 반영되고, Virtual Console 상태 변경이 앱의 준비 안내에 반영되는 것을 확인. 방문 후 약속 완료와 기록 공유까지 시연합니다.

08 / 검증과 판단

“다녀왔는가”와 “다시 쓰고 싶은가”로 평가합니다.

공모전에서 보여줄 증거

  • 차량 특화성: 실제 차량 신호와 경로 연동 결과. 단순 기록 화면과 구분.
  • 핵심 경험: 과거의 약속을 선택해 가족과 조율하고 실제 여정을 완료하는 흐름.
  • 동작 신뢰성: 문만 열기, 좌석에 짐 놓기, 경로만 탐색하기를 방문·탑승·출발로 확정하지 않는지 검증.
  • 복구: 네트워크 단절·휴무 정보·중복 요청에서 계획과 기록이 보존되는지 확인.

사용자에게 확인할 가설

  • 기록에 든 수고보다 다음 방문 준비에서 얻는 도움이 큰가?
  • 가족이 공유 페이지에서 계획 조율에 참여하는가?
  • 과거 기억을 꺼내는 시점이 반갑고 적절한가?
  • 다음 여정 후보가 실제 방문으로 이어지는가?

측정 후보: 기록 수정·완료율, 공유 응답률, 저장 약속의 여정 전환율, 불필요한 확인 횟수. 현재는 사용자 검증 전 가설이며 실적 수치는 없습니다.
