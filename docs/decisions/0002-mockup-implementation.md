# 0002. 목업 구현 방식

- 상태: **Proposed** (결정 필요)
- 날짜: 2026-11-12
- 결정 권장 기한: 2026-11-13. 목업 제작과 영상 녹화 시간을 확보하기 위해서입니다.

## 맥락

목업은 1차 시연 영상의 재료이고, 2차 PT에서 쓸 실제 앱의 출발점입니다. 구현 방식은 아직 정하지 않았습니다. 어떤 방식을 고르든 아래 제약을 지켜야 하며, 결정할 때 각 선택지가 제약을 어떻게 만족하는지 확인합니다.

### 팀 제약

| ID | 제약 |
|---|---|
| T1 | 에뮬레이터를 돌리려면 RTX 3060 Laptop급 이상의 GPU가 필요합니다. 팀원 전원이 돌릴 수 없을 수 있으므로, **에뮬레이터 없이도 화면 작업을 할 수 있어야** 합니다(Fake 차량 데이터, 시나리오 재생). |
| T2 | 마감까지 약 3일이고 프로젝트는 2개입니다. 제작 속도가 중요합니다. |
| T3 | 목업 산출물(화면 흐름, 상태 모델, 데이터 모델)이 Android 구현으로 넘어갈 때 버려지지 않아야 합니다. |
| T4 | 두 프로젝트가 공유하는 개념(차량 신호, 주행/정차 상태, 퀘스트와 여정)을 공통화할 여지가 있습니다. |
| T5 | Claude Code와 Codex가 읽고 고칠 수 있는 텍스트 기반 산출물이 협업에 유리합니다. |
| T6 | 두 프로젝트 모두 주행 중/정차 중에 화면이 달라야 합니다. 목업에서도 상태가 바뀌는 장면을 보여줘야 합니다. |
| T7 | 차량특화성을 전달하려면 영상에 차량 맥락(차량 화면 비율, 차량 신호 변화)이 보여야 합니다. |

## 선택지

| 기준 | A. 웹 클릭 목업 (HTML/TS) | B. Android 앱 (Kotlin, Fake와 실제 SDK 교체 가능) | C. 디자인 도구 프로토타입 (Figma 등) |
|---|---|---|---|
| 1차 영상까지 속도 (T2) | 빠름 | 느림 (빌드·에뮬레이터 세팅 필요) | 빠름 |
| GPU 없는 팀원 참여 (T1) | 가능 | Fake 데이터로 UI 작업 가능. 실제 SDK 검증에는 GPU 필요 | 가능 |
| APK 가산점 (C1) | 없음 | 가능 | 없음 |
| PT로 이어짐 (C2, T3) | 흐름·데이터 모델만 재사용하고 UI는 다시 만듦 | 그대로 발전시킴 | 디자인만 재사용 |
| SDK 실증 (C5) | 불가 (시뮬레이션만) | 가능 | 불가 |
| 에이전트 협업 (T5) | 좋음 | 좋음 | 낮음 (도구·바이너리 의존) |

혼합안:

- **A 또는 C로 1차 → B로 PT:** 1차 영상은 빠르게 만들고, 11/16 이후 Android로 다시 만듭니다.
- **처음부터 B, 일부 화면만 A:** APK 가산점을 노리되 늦어지는 화면은 웹 목업으로 영상을 채웁니다.
